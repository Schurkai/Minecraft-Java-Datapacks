# 여러 번 떠먹는 수프 냄비

상태: v0.7.0-rc1 구현 / 공식 26.2 헤드리스 서버 검증 통과 / 라이브 클라이언트 검증 전

## 목표와 축소 범위

친구들이 거점에서 바닐라 수프를 나눠 먹는 생활형 장난감이다. RPG 버프, 희귀도, 전용 재료 꾸러미와 음식 가치 증가는 넣지 않았다. 입력도 4그릇, 출력도 4그릇이라 음식이나 그릇이 복제되지 않는다.

지원 입력과 출력은 다음 세 바닐라 아이템뿐이다.

| 내부 종류 | 아이템 |
|---:|---|
| 1 | `minecraft:mushroom_stew` |
| 2 | `minecraft:rabbit_stew` |
| 3 | `minecraft:beetroot_soup` |

## 구조와 사용

빈 `minecraft:cauldron` 바로 아래에 일반 `minecraft:campfire[lit=true]`가 있어야 한다. 영혼 모닥불, 물이 든 가마솥, 꺼진 모닥불에는 새 냄비를 등록할 수 없다.

1. 같은 종류의 지원 수프 4개를 인벤토리에 두고 그중 하나를 주 손에 든다.
2. 5.25블록 안의 빈 가마솥을 바라보고 `/trigger tb_soup set 1`을 실행한다.
3. 한 그릇을 뜰 때는 주 손을 비우고 같은 가마솥을 바라본 뒤 `/trigger tb_soup set 2`를 실행한다.
4. 남은 회분을 버리고 등록을 지울 때는 `/trigger tb_soup set 3`을 실행한다. 환불은 없다.

시선 판정은 눈 위치에서 0.25블록 간격으로 0.25–5.25블록의 21지점을 확인한다. 트리거가 없는 플레이어에게는 이 계산을 하지 않는다.

## 소비와 지급 트랜잭션

등록 전에 구조, 기존 냄비, 지원 종류, 같은 아이템 ID 4개와 서버 상한을 모두 확인한다. marker 소환 성공을 확인한 뒤에만 수프 4개를 지운다. 이 사전검사와 소비는 한 서버 명령 호출에서 동기적으로 끝난다. 예상 밖의 부분 소비 1–3개가 발생하면 같은 바닐라 아이템 수를 즉시 돌려주고 임시 marker를 제거한다.

한 회분을 뜰 때는 빈 주 손 슬롯에 `item replace`로 결과를 먼저 놓고 성공 점수가 1일 때만 남은 회분을 줄인다. 따라서 나머지 인벤토리가 가득 차도 주 손이 비어 있으면 안전하고, 지급이 실패하면 회분이 줄지 않는다. 마지막 회분은 같은 함수 안에서 즉시 marker를 제거하므로 같은 틱의 두 번째 플레이어가 중복 지급받지 못한다.

명령의 아이템 조건은 기본 아이템 ID를 기준으로 한다. 사용자 이름·설명·`custom_data`가 붙은 같은 종류의 수프도 4개 계산과 소비에 포함될 수 있지만 출력은 평범한 바닐라 수프다. 사용자 지정 수프는 냄비에 넣지 않는 것이 안전하다.

## 저장 상태와 소유권

가마솥 중심의 `minecraft:marker` 한 개가 다음 상태를 가진다.

- 태그: `toybox.soup_pot`
- `tb_stype`: 수프 종류 1–3
- `tb_sleft`: 남은 회분 1–4

냄비는 공용이며 소유자·팀 잠금은 없다. 서버 전체 등록 수는 `$soup_total tb_data`에 저장하고 64개로 제한한다. v0.7 데이터 버전은 700이며 기존 플레이어에게 `tb_soup` trigger를 초기화한다.

## 성능과 파손 정리

- 매 틱 수프 marker를 검색하지 않는다.
- 일반 사용은 트리거가 들어온 플레이어의 시선 대상 블록과 그 블록 모서리에서 0.9블록 이내 marker 하나만 찾는다.
- 최대 64개의 등록 marker를 6,000틱(5분)마다 한 번 확인한다.
- 가마솥 또는 일반 모닥불이 없어진 marker는 남은 회분을 아이템으로 떨구지 않고 제거한다.
- 꺼진 일반 모닥불은 구조 파손으로 보지 않는다. 보관은 유지되며 다시 피운 뒤에만 한 그릇을 뜰 수 있다.
- 청크가 언로드되어 있으면 marker도 검색되지 않는다. 청크가 다시 로드된 뒤 다음 5분 정리에서 파손 상태를 처리한다.

관리자가 명령으로 marker만 강제 제거하거나 `$soup_total`을 임의 변경하면 64개 계수가 어긋날 수 있다. 전 청크를 강제 로드해 재계산하는 기능은 Realm 비용 때문에 넣지 않았다. 청크당 별도 상한도 구현하지 않았다.

## 언어와 리소스팩

핵심 기능과 바닐라 수프에는 리소스팩이 필요 없다. 선택형 언어 리소스팩을 적용하면 `ko_kr`에서 한국어, 그 외 언어에서 영어 안내가 보인다. 리소스팩이 없으면 데이터팩의 영어 fallback이 표시된다.

## 검증 상태

정적 검증은 21단계 시선, 정확한 구조, 4개 사전검사·소비·부분 환불, 빈 주 손 선지급, 마지막 회분 제거, 64개 상한, 5분 유지보수와 제한 선택자를 검사한다. 공식 26.2 서버 스모크는 구조 2/2, marker 소환, 종류 2, 회분 4, 마지막 회분 제거 뒤 총계 0·잔존 marker 0을 확인했다.

실제 플레이어의 트리거 시선 정확도, 세 수프의 실제 섭취와 그릇 반환, 사용자 지정 수프 경고 UX, 두 플레이어의 마지막 회분 경쟁, 청크 언로드·재로드와 5분 정리, Realms 성능은 아직 실행하지 않았다. 수동 절차는 `SOUP_TEST.md`에 있다.
