# 점프 발판·줄자·분필·분필 나침반 실제 클라이언트 시험

이 문서는 v0.9.0-rc1에 포함된 건축 도구의 수동 시험 절차다. 절차가 존재한다는 사실은 시험 통과를 뜻하지 않는다. 백업된 폐기 가능 월드에서 OP 권한으로 실행하고, 실제 결과를 `TEST_REPORT.md`에 추가할 때는 실행한 항목만 기록한다.

## 준비

1. Java Edition 26.2 정식 클라이언트와 같은 버전의 서버/싱글 월드를 사용한다.
2. 데이터팩과 선택형 리소스팩을 적용하고 `/reload`, `/datapack list enabled`, `/trigger tb_help`를 확인한다.
3. F3 화면으로 실제 좌표와 차원을 기록한다. 멀티 시험은 서로 다른 두 계정을 사용한다.

## 점프 발판

1. 노란색 유광 테라코타 위에 철 중량 압력판을 놓고 위로 공기 5칸을 확보한다. 걸어서 밟았을 때 부양 IV와 느린 낙하 아이콘, 구름 입자, 소리가 한 번 발생하는지 확인한다.
2. 걷기·달리기·웅크리기·일반 점프·낙하 착지로 각각 진입해 실제 최고 높이, 수평 이동량, 착지 피해를 기록한다.
3. 같은 발판 위로 그대로 떨어진다. 다시 발동하면 실패다. 일반 바닥에 착지한 뒤 다시 밟으면 재발동해야 한다.
4. 발판 두 개를 붙여 첫 발판에서 두 번째 발판으로 바로 착지한다. 두 번째는 발동하지 않아야 하며, 일반 바닥을 밟은 뒤에는 작동해야 한다.
5. 압력판 위 5칸 중 첫째부터 다섯째 위치를 각각 돌·횃불·풀로 막아 본다. 모두 발사하지 않고 한 번만 막힘 메시지를 내야 하며, 구조에서 내려갔다 다시 밟으면 재검사해야 한다.
6. 아래 테라코타 또는 압력판을 다른 블록으로 교체해 작동이 중단되는지 확인한다. 노란색 외 유광 테라코타, 일반 돌 압력판, 금 중량 압력판도 작동하면 실패다.
7. 창작 비행, 겉날개 활공, 물속, 보트/말 탑승 상태에서 구조와 겹쳐도 작동하지 않는지 확인한다.
8. 기존 부양 I/V, 느린 낙하를 각각 적용한 상태에서 밟아 효과가 비정상적으로 짧아지거나 영구화되지 않는지 기록한다.
9. 두 플레이어가 같은 발판과 서로 다른 발판을 동시에 밟아 각자 한 번씩만 효과·입자를 받는지 확인한다.

## 줄자

1. 정수 좌표가 분명한 블록에서 `/trigger tb_measure set 1`을 실행한다. 시작 좌표 메시지가 F3의 블록 좌표와 일치해야 한다.
2. X로 3, Y로 4, Z로 12블록 이동해 다시 `/trigger tb_measure set 1`을 실행한다. Δ값 3/4/12, 직선거리 13, 맨해튼 거리 19, 양 끝 포함 크기 4×5×13, XZ 바닥 52, 수직 4면 170, 부피 260을 확인한다.
3. 같은 점, 수직선, 수평선, 대각선과 음수 좌표를 각각 시험한다. 같은 점은 크기 1×1×1, 바닥 1, 수직 4면 4, 부피 1이어야 한다. Δ 부호와 내림 직선거리도 별도로 기록한다.
4. 시작점을 저장한 뒤 `/trigger tb_measure set 2`로 취소한다. 다음 set 1이 새 시작점으로 동작해야 한다.
5. 시작점을 저장하고 네더 또는 엔드로 이동해 끝점을 시도한다. 무소비 거부 메시지가 나와야 하며 원래 차원으로 돌아오면 같은 시작점으로 측정할 수 있어야 한다.
6. 명령 이동을 허용한 시험 월드에서 축 차이 26,000은 계산되고 26,001은 거부되는지 확인한다. 월드 보더 밖으로 이동해야 한다면 이 항목은 실행하지 말고 미실행으로 기록한다.
7. 시작점을 저장한 상태에서 `/reload`, 재접속, 서버 재시작을 각각 거친 뒤 끝점을 잡아 저장 상태가 유지되는지 확인한다.

## 분필

1. 서로 다른 좌표에서 `/trigger tb_chalk set 1`부터 `set 8`까지 저장하고 각 저장 메시지의 좌표를 기록한다.
2. `/trigger tb_chshow set 1`부터 `set 8`까지 실행해 저장 블록 중심 위의 3점 `end_rod` 기둥이 요청자에게 약 5초 보이는지 확인한다.
3. 같은 슬롯을 다른 위치에서 다시 저장해 기존 좌표가 덮어써지는지 확인한다.
4. 초기화된 다른 계정에서 빈 슬롯 표시, `set 0`, `set 9`를 시도해 안전하게 거부되는지 확인한다.
5. 오버월드·네더·엔드에서 각각 저장과 표시를 시험한다. 다른 차원에서 저장 슬롯을 표시하면 거부되어야 한다.
6. 표시 도중 차원 이동 포털을 타면 이전 차원의 표시 상태가 즉시 끝나고 돌아왔을 때 자동 재개되지 않아야 한다.
7. 재접속, `/reload`, 서버 재시작 뒤 1–8번 좌표가 유지되는지 확인한다.
8. 저장 좌표의 청크가 언로드될 만큼 멀리 이동해 표시를 요청한다. 데이터팩은 청크를 강제로 로드하지 않으므로 보이지 않을 수 있으며, 청크 티켓이나 엔티티가 생기지 않아야 한다.

## 분필 나침반

1. 오버월드에서 분필 슬롯 1을 저장한다. 개조하지 않은 일반 나침반 정확히 1개를 주 손에 들고 자수정 조각 1개를 소지한 뒤 `/trigger tb_compass set 1`을 실행한다.
2. 일반 나침반과 자수정이 각각 1개 줄고 비중첩 `분필 나침반 1`이 주 손에 생기는지 확인한다. 이름, 슬롯 번호, 좌표와 오버월드 설명이 저장값과 일치해야 한다.
3. 같은 차원에서 목표의 동서남북과 아주 먼 로드된 위치로 이동해 바늘이 계속 저장 좌표를 가리키는지 확인한다. 목표 위치에 자석석이 없어도 유지되고 목표 블록을 부숴도 각인이 사라지면 안 된다.
4. 네더와 엔드에서 각각 다른 슬롯을 저장해 새 일반 나침반으로 각인한다. 같은 차원에서는 목표를 가리키고 다른 차원으로 들고 가면 바닐라처럼 회전하며, 저장 차원으로 돌아오면 다시 목표를 가리켜야 한다.
5. 빈 슬롯, 자수정 없음, 나침반 없음, 일반 나침반 2개 스택, 이름·설명·인챈트가 있는 나침반, 이미 만든 분필 나침반을 각각 입력한다. 모두 원본 아이템과 재료를 바꾸지 않고 한 번만 거부해야 한다.
6. `/reload`, 재접속과 서버 재시작 뒤 나침반의 이름·설명·좌표·바늘이 유지되는지 확인한다. 목표 청크가 언로드되어 있어도 강제 로드 티켓이나 marker가 생기면 실패다.

## 동시성·정리

1. 두 플레이어가 같은 틱에 점프 발판을 밟고 서로 다른 줄자·분필·나침반 슬롯을 빠르게 반복한다. 래치·좌표·결과·나침반·입자가 다른 플레이어 것과 섞이지 않아야 한다.
2. 한 플레이어의 분필 입자가 요청하지 않은 다른 플레이어에게 보이지 않는지 확인한다.
3. 30분 반복 뒤 `/execute if entity @e[type=minecraft:marker] run say marker-found` 같은 관리자 점검과 서버 저장 크기/로그를 확인한다. Toybox 점프 발판·줄자·분필 때문에 새 엔티티, 예약 함수, 강제 로드 청크가 남으면 실패다.
4. 로그에서 명령·매크로·입자 오류를 확인한다. 재현 절차, 좌표, 차원, 인원, 로그 시각을 함께 기록한다.

## 통과 판정

점프 발판·줄자·분필·분필 나침반 각각의 1인 핵심 경로, 실패 경계, 재접속/재시작, 두 플레이어 동시성까지 실제로 실행한 뒤에만 라이브 클라이언트 게이트를 통과로 기록한다. 실제 Realm 호환은 별도의 업로드·재접속·재시작 시험이 필요하다.
