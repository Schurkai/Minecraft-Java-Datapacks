# 충격 감지 장치 설계

상태: 설계 완료, 미구현

## 목표

낙하 착지, 폭발, 화살 충돌 같은 사건을 레드스톤 신호로 바꾸는 미니게임·함정 제작용 장난감이다. 스컬크 센서의 복제품이 아니라 특정 충격 종류를 선택하는 좁은 장치다.

## 블록 표현

커스텀 블록 없이 `과녁 블록 위 피뢰침` 구조를 감지기로 사용한다. 출력은 과녁 블록 옆에 설치한 비교기/레드스톤을 통해 읽는다. 데이터팩이 블록 엔티티가 아닌 일반 과녁의 출력 세기를 임의 설정할 수 있는지 G0에서 확인한다.

직접 출력 설정이 불가능하면 피뢰침 아래에 `조각된 책장` 또는 `통` 같은 블록 엔티티를 쓰는 방식은 아이템 오염 위험이 있어 채택하지 않는다. 대신 감지 순간 주변에 `redstone_block`을 2틱 배치했다 원상 복구하는 방식도 경쟁 상태와 블록 손실 위험 때문에 금지한다.

안전 대체안은 감지 장치가 소리·입자·채팅/scoreboard 신호만 내고, 명령 블록 없는 순수 레드스톤 출력은 보류하는 것이다.

## 등록

구조를 완성하고 감지 코어 아이템을 든 채 `/trigger tb_sensor set 1`을 실행한다. 6블록 시선 내 구조를 확인하고 전용 marker를 중심에 하나 등록한다. 해체는 소유자 또는 OP 함수로 수행한다.

서버 전체 64개, 청크당 8개 상한. marker는 감지 종류 bitmask와 소유자 ID를 가진다.

## 사건 입력

### 화살 충돌

커스텀 인챈트/탄약의 `hit_block` 문맥에서 주변 3블록 감지기만 찾는다. 모든 화살을 전역 추적하지 않는다. 일반 바닐라 화살까지 감지하려면 공식 projectile_land advancement/게임 이벤트를 데이터팩에서 안정적으로 구독할 수 있는지 G0에서 확인한다.

### 폭발

Toybox 폭렬·폭발 화살·폭약 함수가 공통 `sensor/emit_explosion`을 호출한다. 바닐라 크리퍼/TNT 폭발 전체 감지는 사건 훅이 없다면 지원하지 않는다고 명시한다.

### 낙하 착지

플레이어별 `fall_distance` 또는 낙하 피해 advancement를 사용해 충격 임계값을 넘은 실제 착지만 감지한다. 모든 몹 낙하는 전역 검색이 필요하므로 1차는 플레이어만 지원한다.

## 신호 규칙

- 화살: 세기 5, 4틱
- 폭발: 세기 12, 8틱
- 강한 착지: 세기 `min(15, floor_distance)`, 6틱
- cooldown: 같은 감지기 4틱

겹친 사건은 더 큰 세기를 채택하고 지속시간을 새로 시작한다. 신호 출력 방식이 G0를 통과하지 못하면 scoreboard API만 남긴다.

## 성능과 정리

사건 발생 위치 주변 `marker`를 반경 3~8블록로 제한 검색한다. 감지기 자체 매 틱 검색은 하지 않는다. 활성 출력만 scheduled reset을 가지며 reset 전에 구조가 바뀌면 블록을 수정하지 않고 marker만 정리한다.

## G0 및 합격 기준

- 순수 데이터팩에서 안전한 레드스톤 세기 출력 가능 여부
- 일반 화살 착지 사건 수신 가능 여부
- 플레이어 낙하 착지와 단순 점프 구분
- Toybox 폭발 공통 emit 한 번만 호출
- 감지기 64개, 동시 사건 20회의 mspt
- 감지기 파손/reload/청크 언로드에서 블록 손실·잔존 marker 없음

안전한 블록 출력이 불가능하면 기능 명칭을 `충격 기록기`로 바꾸고 scoreboard/입자 출력만 제공한다.
