# 전용 갈고리 설계

상태: v0.3.0-rc4 구현, 공식 26.2 서버 로드·`/reload`·재시작 통과 / 실제 클라이언트 검증 전
대상: Minecraft Java Edition 26.2 / 데이터팩 107.1

## 1. 변경 이유

RC3 갈고리는 활·쇠뇌의 블록 빗맞힘을 이동 입력으로 바꿨다. 전투 무기와 이동 도구의 역할이 섞였고, 표시 사거리 32블록에 비해 30틱×0.65블록인 실제 이동 한계가 짧았다. 폭렬·균열 사격과도 배타라 활 세팅을 불필요하게 막았다.

RC4에서는 갈고리를 **전용 낚싯대형 도구**로 분리한다. 활·쇠뇌의 특수 사격과 조합 관계가 없으며, 던지는 동작·찌·낚싯줄로 이동 도구라는 입력과 결과가 바로 보이게 한다.

## 2. 아이템

순수 데이터팩은 새 아이템 ID를 등록할 수 없다. 실제 기반은 `minecraft:fishing_rod`이고 다음 컴포넌트로 전용 도구를 표현한다.

- `minecraft:custom_data.toybox.grappling_hook = true`
- `minecraft:item_model = minecraft:tripwire_hook`
- `toybox:grappling I`
- 번역 가능한 이름과 설명, 영어 fallback

기본 철사 덫 갈고리 모델을 사용하므로 외형에 리소스팩이 필요 없다. 기반 아이템이 낚싯대라 낚싯줄 동작도 유지되지만, 손 위치와 줄 렌더링은 실제 클라이언트 시험이 필요하다.

제작법은 낚싯대 + 끈 + 철사 덫 갈고리 + 슬라임볼 + 자수정 조각이다. RC3의 갈고리 인챈트 책 레시피는 삭제했다. 기존 활에 저장된 `toybox:grappling`은 자동 변환하지 않으며 RC4에서는 작동하지 않는다.

## 3. 사용자 규칙

- 던진 찌가 액체 밖의 블록에 안정적으로 닿으면 당김 시작
- 찌 검색 범위: 플레이어로부터 최대 32블록
- 비행 대기: 최대 100틱
- 당김: 최대 100틱
- 공중 속도: 틱당 0.65블록
- 플레이어가 물속일 때 속도: 틱당 0.325블록
- 찌 2블록 이내 도착 시 종료
- 웅크리기, 관전자 전환, 용암, 사망, 로그아웃 세대 변경, 찌 손실, 시간 초과, 이동 후보 막힘 시 종료
- 종료 뒤 재사용 대기시간: 20틱
- 작동 중 약한 느린 낙하

물에 직접 들어간 찌는 걸림을 취소한다. 블록에 걸린 뒤 플레이어만 물에 들어가면 당김 속도가 절반이 된다.

## 4. 사건과 상태

`toybox:grappling`은 `minecraft:projectile_spawned` 효과만 사용한다. 새 `minecraft:fishing_bobber`가 생긴 순간 다음을 수행한다.

1. `execute on origin`으로 낚싯찌의 소유 플레이어를 찾는다.
2. 플레이어가 비활성이고 cooldown이 0일 때 전역 증가 ID를 플레이어와 새 찌에 복사한다.
3. 플레이어에게 `toybox.grappling_active`를 붙이고 비행 대기 상태 `tb_gp=0`으로 시작한다.
4. 활성 플레이어만 매 틱 자기 ID와 같은 찌 하나를 32블록 안에서 찾는다.
5. 바닥 또는 찌 반경 6방향에서 통과 불가 블록을 찾으면 `tb_gp=1`로 전환한다.
6. 당김 상태에서는 찌를 바라보는 로컬 좌표로 다음 이동 후보를 만들고 12개 지점을 검사한 뒤 플레이어를 이동한다.

현재 점수:

- `tb_gid`: 플레이어/찌 연결 ID
- `tb_gt`: 상태별 남은 시간
- `tb_gcd`: 재사용 대기시간
- `tb_gp`: 0 비행 대기, 1 당김
- `tb_leave`, `tb_death`와 스냅샷: 로그아웃·사망 세대 확인

## 5. 충돌과 걸림 판정

낚싯찌의 실제 블록 적중은 인챈트 `hit_block` 효과를 호출하지 않고 충돌 플래그도 명령에 노출되지 않는다. 찌의 공식 폭이 0.25블록이므로 중심에서 0.16블록 떨어진 지점으로 실제 접촉을 근사한다.

- `is_on_ground`, 또는 ±X/±Y/±Z 0.16블록 지점 중 하나가 `#toybox:grappling_passable` 밖
- 현재 찌 블록이 물·용암이 아님

블록 접촉이 없는 공중 정점이나 열린 공간에서 몹에 걸린 찌는 발동하지 않는다. 완전한 collision shape는 읽을 수 없어 꽃·덩굴·열린 문 같은 경계 사례는 수동 조정 대상이다. 걸린 같은 틱에 첫 당김까지 실행해 상태 전환 직후 `$moved=0`으로 취소되지 않게 한다.

당김 이동 후보는 플레이어 발 위치에서 찌의 눈 위치를 바라본 뒤 `^ ^ ^0.65` 또는 물속 `^ ^ ^0.325`로 계산한다. 후보 발·중간·머리 높이의 네 모서리, 총 12점이 모두 공기·동굴 공기·공허 공기·물일 때만 이동한다. 한 틱이라도 막히면 억지로 통과하지 않고 종료한다.

## 6. 멀티플레이와 정리

각 플레이어는 활성 찌 하나만 가진다. 함수 실행 중 플레이어 한 명만 `toybox.grappling_current`로 표시하고 ID가 같은 찌만 처리하므로 다른 사용자의 갈고리를 탈취하지 않는다.

cleanup은 다음을 수행한다.

- 오버월드·네더·엔드에서 같은 ID의 전용 찌 제거
- active/current 태그 제거
- 시간·상태·연결 ID 초기화
- 로그아웃/사망 세대 스냅샷 갱신
- cooldown 20틱 설정

바닐라 3차원 밖 커스텀 차원은 즉시 정리 대상이 아니다. 찌 자체의 바닐라 소유자/수명 동작에 의존하므로 지원 범위 밖이다.

## 7. 성능

- 비활성 플레이어: 기존 플레이어 점수 초기화와 양수 cooldown 감소만 수행
- 활성 플레이어: 최대 32블록의 `fishing_bobber` 1개 조회, 걸림 전 바닥/인접 블록 검사, 걸림 뒤 이동 후보 12점 검사
- 전역 엔티티 매 틱 검색 없음
- 찌 생성은 인챈트 사건에서만 처리
- 차원별 무제한 찌 선택은 활성 사용자의 종료/정리 사건에서만 실행

## 8. 수동 합격 기준

- 전용 제작법, 이름, 기본 갈고리 모델, 낚싯줄 표시
- 바닥·벽 걸림과 공중 정점 거짓 걸림 없음
- 천장 접촉은 걸리거나 안전하게 실패
- 32블록 안/밖, 100틱 시간 초과
- 물에 던지기 취소, 당김 중 입수 시 절반 속도, 용암 취소
- 12점 충돌 검사로 블록·문·울타리·낮은 천장을 통과하지 않음
- 웅크리기·사망·로그아웃·차원 이동 뒤 찌·태그·점수 잔존 없음
- 두 플레이어 동시 사용 시 ID와 찌가 교차하지 않음
- 30분 반복 뒤 찌·태그·점수 누수 없음

공식 서버 자동 시험은 레지스트리, JSON, predicate, 함수와 명령의 로드·`/reload`·재시작까지만 증명한다. 위 조작감과 클라이언트 렌더링은 통과로 기록하지 않는다.

## 9. 보류

- 몹 또는 다른 플레이어 끌기
- 진자 운동과 로프 길이 물리
- 영구 집라인
- 복잡한 충돌 모양에서의 걸림 보장
- 커스텀 차원 즉시 정리
- 월드 보더 중심·크기 선제 판정

이 항목은 순수 데이터팩의 플레이어 Motion·충돌·보더 조회 제약과 멀티플레이 안전 비용 때문에 RC4 범위에서 제외한다.
