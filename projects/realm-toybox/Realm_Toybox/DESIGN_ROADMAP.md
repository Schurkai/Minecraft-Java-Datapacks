# Realm Toybox 설계 로드맵

모든 문서는 Java Edition 26.2 / 데이터팩 107.1을 기준으로 한다. `구현` 표시는 파일이 존재한다는 뜻이며, 공식 서버와 라이브 클라이언트 릴리스 게이트 통과를 뜻하지 않는다.

## 공유 기반

- `tb_data`/storage 데이터 버전 마이그레이션
- 플레이어별 작업 ID allocator와 공통 cleanup
- `translate` + 영어 fallback, 선택형 `ko_kr`/`en_us` 리소스팩
- 개발 지급·검증 함수는 `toybox:dev/...`
- 라이브 수동 시험 준비는 명시적 `/function toybox:dev/client_test_...` 호출로만 실행하고 틱·발전 과제·예약 함수에 연결하지 않음. 리그는 영속 marker 없이 블록만 설치하며, 시험 테이블 위에서 실행하는 cleanup과 폐기 가능한 시험 월드를 요구함
- 기능 설정은 storage, 일반 사용은 기능에 따라 trigger 또는 블록 우클릭 발전 과제, 관리자 변경은 명시적 함수
- 영구 marker는 기본 금지. 블록 상태를 다른 방법으로 저장할 수 없는 수프 냄비처럼 꼭 필요한 경우 서버 상한, 청크 언로드·재시작, 파손 정리 규칙과 비매틱 검색을 필수로 둠
- 실패 전 조건 검사, 성공 뒤 소비. 중간 실패에서 아이템·경험치 소비 금지

## 릴리스 게이트

각 기능은 JSON 정적 검증, 공식 서버 신규 부팅, `/reload`, 재시작 외에 실제 클라이언트 1인 기능 시험과 2인 동시성 시험을 통과해야 한다. 엔티티 또는 아이템을 다루는 기능은 30분 반복 후 누수·복제·손실이 없어야 한다.

v0.4.0-rc2는 요청에 따라 고등 마법부여와 포션 합성을 함께 담은 통합 후보이며, 두 기능의 대표 경계를 준비하는 라이브 클라이언트 수동 키트를 추가했다. 키트가 존재하거나 자동 리그 스모크가 성공하는 것만으로는 실제 클라이언트 1인·2인 게이트를 통과한 것이 아니다. 실제 실행 결과가 기록되기 전에는 정식 생존용 릴리스로 승격하지 않는다.

RC2는 개발용 시험 함수·검증·번역·문서만 추가하고 영구 gameplay state/objective/storage 스키마를 바꾸지 않으므로 데이터 버전은 400을 유지한다.

v0.5.0-rc1은 위험도가 낮은 줄자와 분필 북마크를 추가하고 데이터 버전을 500으로 올렸다. 공식 서버의 소스 시험은 통과했지만 실제 클라이언트·2인 동시성·Realm 게이트는 아직 남아 있다. 특수 화살은 플레이어 발사 탄약의 `custom_data` 보존을 실제 클라이언트에서 증명하는 G0 전에는 구현하지 않는다. 이후 릴리스도 위험도 중 이상 기능은 한 번에 하나씩 추가한다.

v0.6.0-rc1은 두 바닐라 블록 구조로 식별하는 점프 발판과 플레이어별 재무장 래치를 추가하고 데이터 버전을 600으로 올렸다. marker·좌표 등록·전역 엔티티 검색 없이 플레이어 발밑만 검사한다. 공식 서버 소스 게이트는 통과했지만 실제 상승 높이와 2인 동시성은 라이브 클라이언트 게이트 전이다.

v0.7.0-rc1은 입력과 출력이 같은 바닐라 수프 네 그릇인 공용 수프 냄비를 추가하고 데이터 버전을 700으로 올렸다. 트리거 때만 5.25블록 시선과 대상 marker 하나를 찾고, 서버 전체 64개를 5분마다 정리한다. 공식 서버 소스 게이트에서 구조·marker·회분·마지막 제거를 통과했지만 실제 섭취, 2인 마지막 회분, 청크 영속성과 Realm 게이트는 남아 있다. 다음 구현은 특수 화살 `custom_data` G0 또는 충격 감지 장치의 안전한 바닐라 출력 수단이 실제 클라이언트에서 증명되기 전까지 보류한다.

v0.8.0-rc1은 기존 분필 좌표를 `tracked:false` 바닐라 나침반 컴포넌트에 각인하고 줄자에 양 끝 포함 크기·면적·부피를 추가했다. 요청 때만 동기적으로 계산·교체하며 새 영속 엔티티나 강제 로딩이 없다. 공식 서버 소스 게이트에서 3차원 아이템 직렬화와 32비트 산술 경계를 통과했지만 실제 바늘, 플레이어 입력 선검사, 2인 trigger와 Realm 게이트는 남아 있다. 위험도 중 이상 신규 기능 보류 규칙은 그대로 유지한다.
