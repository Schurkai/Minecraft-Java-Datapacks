# 알려진 제한 사항

- 수확 낫은 같은 높이의 3×3만 처리하며 완숙 밀·당근·감자·비트·네더 사마귀 외 작물, 줄기·코코아·달콤한 열매·후렴과 모드 작물은 지원하지 않는다. 자동 재파종은 복제와 부분 실패를 피하기 위해 의도적으로 제외했다.
- 수확 낫의 한 번 수확 비용은 명시적 아이템 수정자로 내구도 1이다. 내구성 인챈트의 확률 감소는 적용하지 않으며 수선과 일반 수리는 그대로 가능하다. 마지막 내구도에서는 직접 파손 처리한다.
- 수확 낫의 5블록 시선은 첫 비공기 블록에서 멈추므로 꽃·키 큰 풀처럼 통과 가능한 비공기 블록도 시야를 막는다. 서로 다른 기반의 작물을 같은 높이에 섞어 놓았을 때만 한 3×3에 함께 들어간다.
- `minecraft:using_item` 진입을 만들기 위해 낫에 매우 긴 `blocks_attacks` 지연을 넣었다. 실제 클라이언트의 사용 자세, 공격/방패 동작과의 간섭, 주·보조 손 우선순위, 키를 계속 누를 때 10틱 재발동 감각은 아직 수동 검증하지 않았다.

- 전용 갈고리는 공식 서버의 레지스트리·함수·명령 파싱과 `projectile_spawned` 스키마까지 검증했지만, 실제 클라이언트에서 낚싯줄 표시, 찌 접촉 판정, 당김 감각, 12점 충돌 경계와 2인 동시 사용은 아직 시험하지 않았다.
- 갈고리 제작 결과의 `custom_data`는 식별·표시용일 뿐 런타임 잠금이 아니다. 명령이나 모루로 `toybox:grappling`을 다른 낚싯대에 강제로 붙이면 전용 이름·외형 없이도 작동할 수 있다.
- 갈고리는 실제 블록 충돌 사건을 받을 수 없어 찌 중심에서 ±0.16블록 6방향과 `is_on_ground`를 검사한다. 공중 정점과 열린 공간의 몹 걸림은 배제하지만 꽃·열린 문처럼 블록 ID와 충돌 모양이 다른 경계는 오판할 수 있다. 물에 직접 던진 찌는 취소되고, 이미 걸린 뒤 플레이어가 물에 들어가면 이동 속도만 절반이 된다.
- 데이터팩 명령으로 임의 설정된 월드 보더의 중심과 크기를 안정적으로 읽을 수 없어 갈고리와 균열 사격은 동적 보더를 선제 검사하지 않는다. 갈고리 정리는 바닐라 오버월드·네더·엔드만 즉시 지원한다.
- 갈고리/균열 사격의 통과 태그는 공기·물만 허용하는 보수적 목록이다. 꽃, 덩굴, 키 큰 풀, 버블 칼럼처럼 실제 충돌이 약한 블록에서도 이동이 거부될 수 있다.
- 도약은 실제 ‘누른 시간’ 값을 읽지 않고 매 틱 점프키가 눌렸는지만 확인한다. 상승 중에만 작동하고, 시선을 수직으로 크게 돌리면 `apply_impulse`의 수직 성분이 약해질 수 있다. 바람 충전구 등 다른 원인으로 상승할 때 점프키를 눌러도 발동한다.
- 도약은 기존 탄성처럼 착지 충격을 줄이거나 낙하 뒤 튕겨 주지 않는다. 낙하 안전 기능이 아니며 실제 입력감과 레벨별 높이는 클라이언트 미검증이다.
- 점프 발판은 노란색 유광 테라코타와 철 중량 압력판의 두 블록 조합만으로 식별한다. 등록 데이터가 없으므로 의도하지 않은 동일 구조도 작동하고, 다른 색·일반 압력판·금 중량 압력판·부분 파손 구조는 작동하지 않는다.
- 점프 발판은 부양 IV 1초와 느린 낙하 3초를 사용한다. 기존 부양/느린 낙하 효과와의 우선순위, 실제 상승 높이, 이동 방향 감각, 낮은 천장 경계는 클라이언트 미검증이다. 위 5칸에 횃불·풀처럼 통과 가능한 비공기 블록이 있어도 보수적으로 거부한다.
- 한 번 발동하거나 막힘 경고를 받은 점프 발판은 일반 바닥에 착지해야 재무장된다. 인접한 발판으로 바로 착지하면 두 번째 발판은 발동하지 않으며, 이 제한은 같은 발판 위 무한 반복을 막기 위한 의도된 축소안이다.
- 균열 사격은 조건 실패 시에도 적중 화살을 제거한다. 성공 피해 5는 저체력 플레이어를 죽일 수 있다. 12점 검사는 몸이 들어갈 공간만 확인하며 지지 바닥은 요구하지 않으므로 절벽이나 공중으로 이동할 수 있다. 짧은 느린 낙하만 제공하며, 실제 충돌 모양이나 월드 보더를 완전하게 모델링하지 않는다.
- 폭렬의 지면 수정은 블록 적중 폭발 중심을 월드 +Y로 0.25블록 옮긴다. 바닥 윗면에는 맞지만 벽·천장 모든 방향을 보장하지 않는다. 창작 비행은 바닐라 폭발 넉백을 받지 않는다.
- 폭렬의 공식 `minecraft:explode` 효과는 자기 피해와 다른 대상 피해를 별도 배율로 나눌 수 없다. 안정적인 1발 상한을 위해 폭렬+다중 발사/관통은 금지했으며, 명령으로 강제한 비호환 조합은 지원하지 않는다. 폭발 보호의 Toybox 넉백 저항 기여는 최대 0.8이지만 다른 속성 공급원이 있으면 총저항이 더 높아질 수 있다.
- 폭렬은 블록/직격 모두 화살을 폭발 source로 사용하므로 소유자 기반 PvP·팀 피해 검사를 따른다. 다만 피해가 차단되어도 폭발 넉백까지 차단된다고 보장할 수 없고, 폭발만으로 난 주변 대상 처치의 통계·사망 메시지가 사수에게 완전히 귀속되지 않을 수 있다.
- 일반 날개 결속 흉갑의 동일 레시피 재투입은 26.2의 no-op 차단으로 거부된다. 다이아몬드 결속 흉갑을 네더라이트로 업그레이드한 뒤 다시 결속하는 경계 사례와 제작 UI 표시는 아직 수동 확인 전이다.
- 결속 재료인 겉날개의 내구도·인챈트는 결과에 복사되지 않는다. 날개 흉갑은 원래 흉갑 재료로 수리되며 수선·내구성도 일반 흉갑 규칙을 따른다.
- 모루의 전역 “너무 비쌉니다!” 상한은 바꾸지 않는다. 트리거는 주 손 아이템의 누적 `repair_cost`만 초기화한다.
- 줄자는 플레이어의 소수 위치가 아니라 명령 실행 시점의 내림된 정수 블록 좌표를 사용한다. 직선거리는 `sqrt(dx²+dy²+dz²)`의 내림값이며 축별 차이가 26,000블록을 넘으면 scoreboard overflow를 피하기 위해 계산을 거부한다. 크기·면적·부피는 두 끝 블록을 포함하므로 각 축이 `abs(Δ)+1`이다. 수직 4면 또는 부피가 signed 32-bit를 넘으면 거리 결과는 유지하고 해당 큰 값만 생략한다.
- 줄자와 분필은 오버월드·네더·엔드만 지원한다. 줄자는 다른 차원에서 끝점을 잡을 수 없고, 분필은 저장한 차원과 현재 차원이 다르면 표시하지 않는다. 커스텀 차원은 안전하게 거부한다.
- 분필은 슬롯 8개를 숫자로만 관리하며 새 저장은 기존 슬롯을 덮어쓴다. 슬롯 이름, 전체 목록 UI, 삭제 명령, 월드에 영구히 보이는 표식은 없다. 표시 요청자에게만 5초간 입자를 보내고 표식 청크를 강제 로드하지 않으므로 멀리 있거나 청크가 로드되지 않으면 보이지 않을 수 있다.
- v0.9.0-rc1에 포함된 점프 발판·줄자·분필·분필 나침반·수확 낫은 공식 서버 명령 파싱과 자동 스모크까지 검증했지만 실제 클라이언트의 이동·좌표·입자·나침반 바늘·낫 사용 키, 재접속 상태 유지, 2인 동시 실행은 아직 시험하지 않았다.
- 분필 나침반은 개조하지 않은 일반 나침반 정확히 1개만 입력으로 받는다. 이름·설명·인챈트·각인 등 저장 컴포넌트가 이미 있는 나침반은 덮어쓰지 않으며, 기존 분필 나침반을 다른 슬롯으로 재각인하는 기능도 없다.
- 목표는 `tracked:false`이므로 실제 자석석이 없어도 유지되고 목표 청크를 강제로 로드하지 않는다. 저장 차원 밖에서는 바닐라 자석석 나침반과 마찬가지로 방향이 무작위 회전하며 커스텀 차원 슬롯은 지원하지 않는다.
- 공식 서버 스모크는 실제 나침반 아이템의 세 차원 resource ID, 좌표, `tracked:0b`, 이름·설명·식별 데이터와 최대 스택 1을 확인했다. 플레이어 전용 `SelectedItem.count/components` 입력 검사, 자수정 소비, 화면의 바늘 방향과 언어별 툴팁은 실제 클라이언트 전까지 통과로 기록하지 않는다.
- RC3 이하의 갈고리 책·갈고리 활은 전용 RC4 갈고리로 자동 변환되지 않는다. 마이그레이션은 새 레시피만 해금하며 기존 활의 저장 인챈트는 작동하지 않는다.
- 선택형 언어 리소스팩 JSON과 키 대응은 자동 검증했지만 실제 클라이언트의 한국어↔영어 전환 화면은 아직 확인하지 않았다.
- 공식 26.2 전용 서버의 로드·`/reload`·재시작 성공은 Realms 업로드 허용을 증명하지 않는다. 커스텀 인챈트 레지스트리가 있는 월드의 실험 기능 경고, 업로드, 재접속과 재시작은 실제 Realm에서 미검증이다. `/datapack list`의 `(world)`/`(세계)` 표시는 출처일 뿐 호환 판정이 아니다.
- v0.4.0-rc2에서 들어온 고등 마법부여와 포션 합성은 v0.9.0-rc1에도 포함되어 있으나, 실제 클라이언트 수동 테스트는 아직 실행하지 않았다. RC2가 추가한 수동 테스트 키트도 시험 준비 도구일 뿐이며, 자동 정적 검사나 헤드리스 공식 서버 스모크가 최종 사용감, UI 상호작용, 2인 동시 사용을 증명하지는 않는다.
- `/function toybox:dev/client_test_kit`은 현재 경험치 레벨과 점수를 0으로 만든 뒤 정확 예산 227레벨을 지급한다. 기존 아이템과 섞이거나 지급 아이템이 인벤토리 밖으로 나가는 일을 피하려면 OP 권한, 빈 인벤토리, 열린 공간의 폐기 가능하거나 백업된 시험 월드가 필요하다. 생존 월드용 복구 기능이 아니다.
- 테스트 리그는 실행자의 수평 시선 전방 8블록에 `keep`으로 놓이므로 지형을 덮어쓰지는 않지만, 자리가 차 있으면 일부만 설치될 수 있다. 설치 메시지가 활성 책장 `60/60`이 아니면 결과를 유효한 시험으로 기록하면 안 된다.
- `/function toybox:dev/client_test_cleanup`은 실행자가 시험 마법부여대 바로 위에 서 있어야 한다. 영속 marker와 엔티티 검색은 없으며 자동 로그아웃·재시작 정리도 없다. 발밑 원점 슬롯의 책장·마법부여대·양조기는 원래 블록인지 키트가 놓은 블록인지 구분할 수 없어 같은 종류의 기존/교체 블록도 제거할 수 있다.
- 키트 정리는 전용 `custom_data` 태그가 남은 지정 종류의 아이템을 지운다. 강화 검은 비대상 컴포넌트와 함께 시험 태그도 보존하므로 정리 명령이 강화 결과까지 삭제한다. 새 혼합 물약은 입력의 시험 태그를 보존하지 않아 남고, 던지거나 마신 효과와 지급·소비된 경험치도 제거하거나 원래대로 복원하지 않는다. 따라서 보존 결과를 먼저 기록해야 하며 정리 명령만으로 시험 전 상태가 복원되지는 않는다.
- 키트의 정확 예산 경로는 날카로움 V→X 한 종류, 신속 강도·시간 합성, 서로 다른 5효과 합집합, `strong_turtle_master` 거부만 다룬다. 다른 13종 고등 인챈트, 포션 효과 40종, 빠른 손 교체, 인벤토리 경계, 2인 동시성, 장시간 누수, 실제 Realm은 별도 수동 시험이 필요하다.
- 고등 마법부여는 주변의 모든 책장을 세지 않는다. 마법부여대 기준으로 코드에 정의된 **60개 고정 슬롯**만 검사하며, 각 슬롯과 중앙 사이의 지정 전송 통로가 허용 블록이어야 활성 책장으로 계산한다. 임의 배치, 대각선 우회 통로, 60개 밖의 책장은 인정하지 않는다.
- 고등 마법부여는 보조 손 책에 지원 인챈트가 정확히 하나 있고, 주 손 장비와 책의 현재 레벨이 같은 경우에만 한 단계 올린다. 지원 목록과 개별 상한 밖의 인챈트, 저주·수선·무한 같은 기능형 인챈트는 처리하지 않는다.
- 고등 마법부여는 `item modify`로 대상 인챈트만 교체하도록 구현되어 다른 컴포넌트를 보존해야 한다. 다만 이름·내구도·장식·수리 비용·다른 인챈트·임의 사용자 데이터를 모두 조합한 실제 클라이언트 보존 시험은 아직 실행하지 않았다.
- 포션 합성은 입력의 `potion_contents`만 정규화해 새 병을 만든다. 입력 병의 사용자 이름, lore, custom color, custom model/data 및 그 밖의 비포션 컴포넌트는 보존하지 않으며 결과는 고정 보라색 `Mixed Potion`으로 재구성된다.
- 한 입력 병 안에서 기본 효과와 custom effect가 같은 ID를 공유하거나 custom effect 목록 자체에 중복 ID가 있으면 합성을 거부한다. 두 입력이 모두 단일 효과이고 ID가 같을 때만 강도/시간 합성이 가능하며, 다중 효과 병 사이에 하나라도 겹치는 ID가 있으면 전체 합성을 거부한다.
- 공식 `strong_turtle_master`에는 감속 VI(amplifier 5)가 포함되어 포션 시스템의 V 상한을 넘는다. 이 병은 V로 낮춰 바꾸지 않고 입력 단계에서 무소비로 거부한다.
- 포션의 내부 duration 상한은 72000틱이다. 잔류형 물약은 바닐라 아이템의 `potion_duration_scale=0.25`를 그대로 사용하므로 같은 내부 duration이라도 표시·적용 시간은 일반형의 25%이며, 72000틱 결과는 잔류형에서 최대 18000틱(15분)이다. 투척형의 실제 시간은 적중 거리에 따라 추가로 달라질 수 있다.
- 물병·평범한 물약·진한 물약·어색한 물약처럼 정규화 뒤 효과가 0개인 입력은 합성할 수 없다. `hidden_effect`, I–V 밖의 단계, 1–72000틱 밖의 지속시간도 안전하지 않은 입력으로 거부한다.
- 포션 합성은 양조기 UI의 슬롯이나 바닐라 양조 레시피를 확장하지 않는다. 두 손에 병을 든 채 양조기를 우클릭하는 별도 사건 기반 기능이며, 결과 적용 뒤 입력과 비용을 소비한다.
- 수프 냄비는 안정적인 바닐라 우클릭 사건을 억지로 만들지 않고 명시적 `/trigger tb_soup set 1/2/3`을 사용한다. 시선은 눈에서 0.25블록 간격으로 최대 5.25블록만 검사하므로 아주 비스듬한 가마솥 모서리나 사거리 경계의 실제 조작감은 클라이언트 미검증이다.
- 수프 냄비는 주 손의 기본 아이템 ID와 같은 수프를 인벤토리에서 센다. 이름·설명·`custom_data` 등 사용자 컴포넌트가 붙은 같은 종류도 소비될 수 있고 결과는 평범한 바닐라 수프로 나온다. 사용자 지정 수프의 컴포넌트 보존은 지원하지 않는다.
- 수프 냄비는 공용이며 소유자·팀 잠금, 회분 보충, 다른 종류 섞기, 남은 수프 환불, 청크당 상한이 없다. 서버 전체 64개 계수는 `$soup_total tb_data`에 저장되므로 관리자가 marker만 `/kill`하거나 점수를 직접 바꾸면 어긋날 수 있다.
- 가마솥이나 일반 모닥불이 파손된 냄비는 로드된 marker를 5분마다 검사해 환불 없이 제거한다. 언로드된 청크는 검사하지 않으며 청크가 다시 로드된 다음 유지보수 주기까지 고아 marker와 전역 개수가 남을 수 있다. 꺼진 모닥불은 파손으로 처리하지 않고 재점화 전까지 지급만 막는다.
- 수프 냄비의 구조·marker·종류·4회분·마지막 제거와 유지보수는 공식 서버 스모크를 통과했지만 실제 플레이어 시선, 섭취와 그릇 반환, 두 플레이어의 마지막 회분 경쟁, 64/65개 경계, 재접속·청크 언로드·Realms는 아직 시험하지 않았다.
- 철퇴 급강하, 소모성 특수 화살, 충격 감지 장치와 특수 폭약은 설계 문서만 있으며 v0.9.0-rc1에 포함되지 않는다. 구현된 작은 장난감은 도약, 점프 발판, 줄자, 분필 북마크·나침반, 수프 냄비와 수확 낫이다.
