# 수프 냄비 수동 시험

이 문서는 v0.7에서 도입되어 v0.9.0-rc1에도 포함된 수프 냄비의 실제 클라이언트 시험 절차다. 절차가 존재한다는 사실은 통과를 뜻하지 않는다. 백업한 폐기 가능 월드에서 실행하고 실제로 확인한 결과만 `TEST_REPORT.md`에 기록한다.

## 준비

- Java Edition 26.2 정식 클라이언트와 v0.9.0-rc1 데이터팩
- OP 권한이 있는 시험 월드
- 일반 모닥불, 가마솥, 부싯돌과 부시
- 버섯 스튜·토끼 스튜·비트 수프 각각 5개 이상
- 필요하면 두 번째 플레이어

## 1인 기능

1. 받침 블록 위에 일반 모닥불, 그 바로 위에 빈 가마솥을 놓고 모닥불을 피운다.
2. 버섯 스튜 4개 중 하나를 주 손에 들고 5블록 안에서 가마솥을 바라본 뒤 `/trigger tb_soup set 1`을 실행한다.
3. 정확히 4개가 사라지고 등록 성공 메시지가 한 번 나오는지 확인한다.
4. 주 손에 다른 아이템을 든 채 `set 2`를 실행해 아무 회분도 줄지 않고 빈손 안내가 나오는지 확인한다.
5. 주 손을 비우고 `set 2`를 네 번 실행한다. 매번 버섯 스튜가 주 손에 생기고 남은 수가 3, 2, 1, 0으로 표시되는지 확인한다.
6. 각 결과를 먹어 바닐라 포만감과 빈 그릇 반환이 정상인지 확인한다.
7. 다섯 번째 `set 2`가 아이템을 주지 않고 등록되지 않은 냄비로 안내하는지 확인한다.
8. 토끼 스튜와 비트 수프로 2–7을 반복한다.

## 실패와 파손

- 수프 0/1/2/3개, 지원하지 않는 음식, 영혼 모닥불, 꺼진 모닥불, 물 가마솥, 모닥불 없는 가마솥에서 등록이 무소비로 실패하는지 확인한다.
- 이미 등록된 가마솥에 다시 `set 1`을 실행해 두 번째 4개가 소비되지 않는지 확인한다.
- 인벤토리의 다른 칸을 가득 채우고 주 손만 비운 상태에서 한 회분을 받아 회분 손실이 없는지 확인한다.
- 모닥불만 끈 뒤 보관이 유지되고 `set 2`가 거부되는지, 다시 피우면 남은 회분을 받을 수 있는지 확인한다.
- 등록 뒤 가마솥 또는 모닥불을 부수고 5분 이상 로드 상태로 둔 다음 같은 자리에 구조를 다시 만들었을 때 이전 회분이 되살아나지 않는지 확인한다.
- 남은 회분이 있을 때 `/trigger tb_soup set 3`으로 제거하고 아이템 환불이나 바닥 드롭이 없는지 확인한다.

## 동시성과 영속성

- 두 플레이어가 회분 1인 냄비를 동시에 바라보고 `set 2`를 실행한다. 수프는 정확히 한 명에게 한 개만 지급되어야 한다.
- 두 플레이어가 다른 냄비를 같은 틱에 등록·사용해 종류와 회분이 섞이지 않는지 확인한다.
- 회분이 남은 냄비로 `/reload`, 서버 재시작, 청크 언로드·재로드를 각각 거친 뒤 종류와 남은 수가 유지되는지 확인한다.
- 64개 등록 성공과 65번째 무소비 거부를 확인한 뒤 `set 3`으로 하나를 지워 새 등록이 다시 가능한지 확인한다.
- 30분 반복 뒤 `/execute as @e[type=minecraft:marker,tag=toybox.soup_pot] run data get entity @s Pos`로 예상한 냄비 수만 남는지 확인한다. 이 명령은 진단용이며 marker를 수정하지 않는다.

## 기록

클라이언트 언어 `ko_kr`와 다른 언어, 선택형 리소스팩 미적용 상태의 영어 fallback도 각각 확인한다. 실패한 항목은 입력 수프 종류, 좌표·차원, 남은 회분, 동시 사용자 수, `/reload`·재시작 여부와 함께 기록한다.
