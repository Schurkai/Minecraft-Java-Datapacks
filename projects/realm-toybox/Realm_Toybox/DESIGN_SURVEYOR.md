# 측량가 업데이트 설계

상태: v0.8.0-rc1 구현 / 공식 Java 26.2 소스 서버 검증 통과 / 릴리스 ZIP 결과는 TEST_REPORT 참조 / 라이브 클라이언트·Realm 검증 전

기준: Java Edition 26.2 정식판, 데이터팩 형식 107.1, 선택형 리소스팩 형식 88.0.

## 목표

- 기존 줄자의 두 점을 건축에 바로 쓸 수 있는 포함 크기·면적·부피로 확장한다.
- 기존 분필 슬롯 1–8을 가리키는 바닐라 나침반형 도구를 만든다.
- 목표 청크, 엔티티, 자석석, 매 틱 좌표 계산에 의존하지 않는다.
- 사용자 지정 나침반의 컴포넌트를 조용히 파괴하지 않는다.

## 줄자 산술

시작과 끝의 정수 블록 좌표 차이를 `dx,dy,dz`, 절댓값을 `ax,ay,az`라 한다. 기존 Δ 부호, 내림 직선거리와 맨해튼 거리는 그대로 유지한다.

건축 크기는 양 끝 블록을 모두 포함한다.

- `X=ax+1`
- `Y=ay+1`
- `Z=az+1`
- XZ 바닥 면적: `X×Z`
- 수직 4면의 면적 합: `2×(X×Y+Y×Z)`
- 포함 부피: `X×Y×Z`

기존 축 차이 상한 26,000 때문에 span은 최대 26,001이고 두 축 곱은 최대 676,052,001이다. 따라서 두 축 곱까지는 signed 32-bit에 안전하다.

수직 4면은 `X×Y+Y×Z <= 1,073,741,823`일 때만 마지막 2배를 수행한다. 부피는 `X×Y <= floor(2,147,483,647/Z)`일 때만 마지막 곱을 수행한다. 큰 값은 0이나 음수로 감싸지지 않고 해당 결과만 “생략”으로 표시한다.

## 분필 나침반 사용

1. `/trigger tb_chalk set 1..8`로 목표를 저장한다.
2. 주 손에 개조하지 않은 일반 `minecraft:compass` 정확히 1개를 든다.
3. 인벤토리에 자수정 조각 1개를 준비한다.
4. `/trigger tb_compass set 1..8`을 실행한다.

성공 결과는 최대 스택 1인 새 나침반이며 다음 컴포넌트를 가진다.

- `minecraft:lodestone_tracker`: 분필 좌표와 차원, `tracked:false`
- `minecraft:custom_name` / `minecraft:lore`: 슬롯, 좌표와 차원
- `minecraft:custom_data.toybox.chalk_compass`: 버전, 슬롯, 좌표와 차원
- `minecraft:max_stack_size=1`

`tracked:false`는 실제 자석석 확인을 끄므로 목표 블록이 바뀌어도 각인이 사라지지 않는다. 나침반 자체의 바닐라 렌더러가 같은 차원에서 목표를 가리키며 다른 차원에서는 회전한다.

## 입력과 트랜잭션

다음 순서로 실패 이유를 하나만 결정한다.

1. 슬롯이 비어 있지 않고 차원이 오버월드·네더·엔드 중 하나인지 검사한다.
2. 주 손이 일반 나침반인지 검사한다.
3. `SelectedItem.count`가 정확히 1인지 검사한다.
4. `SelectedItem.components`가 없음을 검사해 사용자 지정·기존 각인 나침반을 보호한다.
5. 자수정 조각 1개를 소지했는지 검사한다.
6. 함수 매크로 `item replace` 성공값이 1일 때만 자수정 1개를 소비한다.

좌표 매크로용 `toybox:scratch compass`는 함수 시작과 끝에서 삭제한다. trigger 호출은 한 서버 스레드에서 동기적으로 끝나므로 다른 플레이어의 좌표와 섞이지 않는다.

## 성능

- `tb_compass`는 다른 trigger처럼 매 틱 활성화만 한다.
- 실제 좌표 복사와 아이템 교체는 점수가 요청된 플레이어에게 한 번만 실행한다.
- 목표 좌표를 향한 매 틱 벡터 계산이나 파티클은 없다.
- marker·갑옷 거치대·아이템 엔티티·예약 함수·`forceload`를 gameplay에 만들지 않는다.
- 공식 서버 스모크의 갑옷 거치대와 barrel은 개발 함수 안에서만 생성하고 같은 호출에서 제거한다.

## 검증 경계

자동 검증은 포함 산술의 정상값과 26,001 span 최대값, 3개 차원의 `lodestone_tracker`, `tracked:0b`, 좌표, 이름·설명, 식별 데이터, 최대 스택 1, 임시 엔티티·블록 정리를 확인한다.

헤드리스 서버는 실제 플레이어 `SelectedItem` 선검사, 자수정 소비, 화면의 바늘 회전, 언어별 툴팁과 두 플레이어 동시 trigger를 증명하지 못한다. 이 항목은 `BUILDING_TEST.md`의 라이브 클라이언트 게이트로 남긴다.
