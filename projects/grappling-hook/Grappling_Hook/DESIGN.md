# 갈고리 데이터팩 기획

상태: v0.1.0-rc1 구현 완료 / 실제 클라이언트 검증 전
작업명: **갈고리** (`Grappling Hook`)
대상: Minecraft Java Edition 정식 26.2 / 데이터팩 형식 107.1
배포 형태: 순수 데이터팩 + 선택 리소스팩

## 1. 한 줄 정의

2024 만우절 스냅샷의 `Lashing Potato`에서 착안한, **낚싯줄을 블록에 걸어 플레이어를 빠르게 견인하는 바닐라 플러스 이동 도구**다.

원작의 진자·장력 물리를 그대로 복제하는 것이 아니라, Realm에서 안정적으로 작동하는 `갈고리 발사기/집라인` 감각을 목표로 한다.

## 2. 제품 결정

- `인챈트플러스`에는 넣지 않는다.
- 별도 데이터팩과 별도 네임스페이스 `grapple`로 만든다.
- `Enchant_Plus`와 동시에 설치할 수 있어야 한다.
- 커스텀 인챈트, 커스텀 차원, 커스텀 피해 유형 등 동적 레지스트리를 추가하지 않는다.
- 세계의 실험적 기능을 요구하지 않는다.
- 리소스팩은 언어·외형 개선용 선택 사항이며 핵심 기능에는 필요하지 않다.
- 모드와 서버 플러그인은 사용하지 않는다.

예정 배포명:

- `Grappling_Hook_v0.1.0-rc1-java-26.2.zip`
- `Grappling_Hook_Resources_v0.1.0-java-26.2.zip`

## 3. 핵심 조작

1. 갈고리를 **주 손**에 들고 우클릭한다.
2. 낚싯찌가 액체가 아닌 블록에 닿으면 줄이 고정된다.
3. 플레이어가 고정점 쪽으로 자동 견인된다.
4. 다시 우클릭하거나 웅크리면 즉시 해제한다.
5. 고정점에서 약 2.25블록 이내에 도착하면 자동 종료한다.

실패 조건:

- 사거리 밖으로 나감
- 찌가 물 또는 용암에 들어감
- 찌가 몹이나 다른 플레이어에게만 걸림
- 이동 경로가 계속 막힘
- 시간 초과
- 플레이어 사망·로그아웃·차원 이동
- 관전자 전환, 탈것 탑승 또는 겉날개 비행 시작

## 4. 아이템

순수 데이터팩은 새 아이템 ID를 만들 수 없으므로 실제 아이템은 `minecraft:fishing_rod`를 사용한다.

식별 구성요소:

- `minecraft:custom_data.grapple.hook = true`
- 스키마 버전 `minecraft:custom_data.grapple.version = 1`
- 번역 가능한 이름과 설명
- 기본 표시 모델 `minecraft:tripwire_hook`
- 불규칙한 바닐라 낚시 내구도 소비를 막기 위해 내구도 소모 없음

한국어 기본 이름: `갈고리`
영어 이름: `Grappling Hook`

기본 설명:

- `블록에 던지면 그쪽으로 당겨집니다.`
- `다시 사용하거나 웅크리면 해제합니다.`
- `최대 사거리: 30블록`

리소스팩이 없으면 한국어 fallback을 표시한다. 선택 리소스팩을 적용하면 `ko_kr`은 한국어, 나머지 언어는 영어 fallback을 사용한다.

## 5. 제작법과 획득 시점

작업대 배치안:

```text
실  철사 덫 갈고리  실
철괴    낚싯대      철괴
빈칸      돌풍구     빈칸
```

소모 재료:

- 낚싯대 1
- 실 2
- 철사 덫 갈고리 1
- 철괴 2
- 돌풍구(`minecraft:wind_charge`) 1

의도:

- 낚싯대와 줄이라는 동작을 직관적으로 설명한다.
- 돌풍구를 요구해 초반 이동을 지나치게 무력화하지 않는다.
- 네더나 엔드 이전에 얻을 수 있는 중반 장난감으로 둔다.
- 사용마다 탄약을 소비시키지는 않는다. 성능은 사거리와 재사용 대기시간으로 제한한다.

| 실패 후 대기시간 | 0.5초(10틱) |
| 물속 견인 속도 | 지상 기준의 50% |

거리별 견인 속도:

| 고정점 거리 | 틱당 이동량 | 초당 환산 |

## 7. 상태 흐름

```text
IDLE
  └─ 갈고리 사용 감지 → CLAIMING
       ├─ 자기 낚싯찌 연결 성공 → FLYING
       └─ 3틱 안에 연결 실패 → FAIL

FLYING
  ├─ 비액체 블록 접촉 → LATCHED
  ├─ 물·용암·몹만 접촉 → FAIL
  ├─ 30블록 초과·60틱 초과 → FAIL
  └─ 재사용·웅크리기 → CANCEL

LATCHED
  ├─ 안전한 이동 후보 존재 → PULLING
  └─ 잘못된 고정점 → FAIL

PULLING
  ├─ 2.25블록 이내 → FINISH
  ├─ 재사용·웅크리기 → CANCEL
  ├─ 4틱 연속 이동 불가 → BLOCKED
  └─ 사망·로그아웃·차원·상태 변화 → CLEANUP

FINISH / FAIL / CANCEL / BLOCKED
  └─ 찌와 상태 정리, 대기시간 설정 → IDLE
```

## 8. 실험 기능 없는 발동 구조

기존 `Realm_Toybox` 시제품은 `toybox:grappling` 커스텀 인챈트의 `minecraft:projectile_spawned` 효과로 새 찌를 잡았다. 이 방식은 동적 인챈트 레지스트리를 추가하므로 이번 팩에서는 사용하지 않는다.

대신 다음 흐름을 사용한다.

1. `minecraft.used:minecraft.fishing_rod` 통계 objective와 직전 값을 플레이어별로 비교한다.
2. 값이 증가했을 때 주 손이 `grapple.hook=true`인 낚싯대인지 확인한다.
3. 비활성 상태라면 플레이어 반경 5블록에서 아직 연결되지 않은 새 `fishing_bobber`만 최대 3틱간 찾는다.
4. 후보 찌에서 `execute on origin`으로 소유자를 확인하고, 현재 사용자와 같은 경우에만 연결한다.
5. 플레이어와 찌에 같은 증가형 연결 ID를 저장한다.
6. 이미 활성 상태에서 사용 통계가 다시 증가하면 수동 해제로 처리한다.

주 손 전용으로 제한하는 이유는 일반 낚싯대와 갈고리를 양손에 동시에 들었을 때 어느 손의 사용이 통계를 올렸는지 데이터팩이 직접 알 수 없기 때문이다.

### 구현 중단 조건

아래 조건 중 하나라도 실제 2인 시험에서 재현되면 커스텀 인챈트 방식으로 후퇴하지 않고 Realm용 출시를 보류한다.

- 같은 위치에서 동시에 던졌을 때 다른 사람의 찌를 연결함
- 첫 사용과 회수 사용을 안정적으로 구분하지 못함
- 사용 통계 갱신보다 찌가 너무 빨리 멀어져 반복적으로 연결에 실패함
- 리로드·재접속 뒤 일반 낚싯대가 갈고리로 오인됨

## 9. 찌 비행과 고정

### 기본안

바닐라 낚싯찌 궤적을 유지한다. 투사체와 줄이 클라이언트에 기본 렌더링되므로 리소스팩 없이도 고정 위치가 잘 보인다.

고정 판정:

- `is_on_ground`, 또는 찌 중심 기준 ±X/±Y/±Z의 짧은 표본점 중 하나가 통과 불가 블록
- 찌가 있는 블록과 인접 액체가 물·용암이 아님
- 몹만 맞고 주변에 블록 접촉이 없으면 고정하지 않음

꽃, 덩굴, 열린 문, 울타리처럼 충돌 모양이 블록 전체와 다른 대상은 별도 수동 시험으로 통과 태그를 조정한다.

### 원작에 가까운 선택안

연결 직후 찌의 `NoGravity`와 운동을 안전하게 제어할 수 있는지 시험한다. 서버·클라이언트 위치가 어긋나지 않고 블록 충돌도 유지되는 경우에만 더 빠르고 평평한 궤적을 사용한다.

다음 현상이 하나라도 있으면 선택안은 폐기하고 기본 궤적으로 출시한다.

- 낚싯줄 끝과 실제 판정 위치가 다름
- 찌가 벽을 통과함
- 고무줄 현상 또는 위치 되감기가 보임
- 다른 플레이어 화면에서 줄이 떨리거나 끊김

## 10. 견인 이동

순수 데이터팩은 플레이어의 `Motion`을 안정적으로 직접 설정할 수 없다. 따라서 고정점을 바라보는 로컬 좌표로 작은 텔레포트를 반복한다.

각 틱 처리:

1. 활성 플레이어의 연결 ID와 같은 찌 하나만 30블록 안에서 찾는다.
2. 플레이어에서 고정점까지 거리에 따라 이동량을 고른다.
3. 이동 후보 위치의 발·허리·머리 높이, 각 네 모서리 총 12점을 검사한다.
4. 직접 이동이 막히면 절반 이동량으로 한 번 더 검사한다.
5. 고정점이 위쪽에 있을 때만 0.35블록 위 후보를 추가로 검사해 낮은 턱을 넘는다.
6. 네 틱 연속 모든 후보가 막히면 안전하게 해제한다.

이동 중에는 짧은 `slow_falling`을 계속 갱신하고, 정상 도착 때만 10틱간 더 유지한다. 수동 해제나 실패 뒤의 추락 위험까지 완전히 없애지는 않는다.

의도적으로 하지 않는 것:

- 벽을 뚫는 이동
- 진자 운동 계산
- 플레이어가 가진 기존 수평 속도의 정확한 보존
- 갈고리를 이용한 무한 비행
- 충돌을 무시한 목표 지점 순간 이동

## 11. 취소와 정리

즉시 정리 대상:

- 두 번째 우클릭
- 웅크리기
- 관전자 모드
- 사망 또는 재접속 세대 변화
- 차원 변경
- 탈것 탑승
- 겉날개 비행
- 머리나 발이 용암에 닿음
- 찌 손실
- 시간 초과

정리 작업:

- 자기 연결 ID의 찌만 제거
- 플레이어의 active/current/pending 태그 제거
- 연결 ID, 타이머, 상태, 연속 막힘 점수 초기화
- 종료 사유에 맞는 대기시간 설정
- 다른 플레이어의 찌와 일반 낚싯찌는 건드리지 않음

로그아웃이나 차원 이동 때 바닐라가 소유자의 낚싯찌를 제거하는 동작을 우선 이용한다. 고아 찌를 찾기 위한 전역 엔티티 매 틱 검색은 넣지 않는다.

## 12. 멀티플레이와 성능

비활성 플레이어:

- 낚싯대 사용 통계 변화와 양수 cooldown만 확인
- 엔티티 검색 없음

새로 사용한 플레이어:

- 최대 3틱 동안 반경 5블록의 낚싯찌만 검색
- 모든 후보는 `execute on origin` 소유자 확인

활성 플레이어:

- 반경 30블록에서 `grapple.anchor` 태그가 있고 자기 ID와 같은 찌만 처리
- 비행 중 고정 판정은 상수 개수 표본
- 견인 중 충돌 판정은 최대 두세 후보의 상수 개수 표본

금지:

- 틱 진입점의 범위 없는 `@e`
- 모든 투사체 매 틱 검색
- 모든 블록에 대한 레이캐스트
- 청크 강제 로드
- 장기 상주 marker 또는 display 엔티티

검증기는 틱 호출 그래프를 따라 범위 없는 엔티티 선택자를 오류로 처리한다.

## 13. 시각·소리

리소스팩 없이 제공:

- 바닐라 낚싯줄
- 철사 덫 갈고리 아이콘/손 모델
- 고정 성공: 사슬 설치음 + 작은 `crit` 입자
- 견인: 낮은 음량의 사슬음, 과도한 매 틱 소리는 금지
- 도착: 철문 닫힘 계열 짧은 소리
- 실패: 약한 베이스 음

선택 리소스팩:

- 갈고리 전용 2D 아이콘
- 한국어/영어 번역
- 핵심 판정이나 기능은 리소스팩에 의존하지 않음

액션바는 실패 이유나 cooldown을 알릴 필요가 있을 때만 표시하고, 정상 견인 중에는 화면을 가리지 않는다.

## 14. 다른 기능과의 관계

- `Enchant_Plus`: 별도 네임스페이스와 objective를 사용해 동시 설치 지원
- 날개 결속 흉갑/겉날개: v0.1 견인 중 활공은 취소해 충돌과 운동량 문제를 피함
- 일반 낚싯대: custom data가 없으면 절대 처리하지 않음
- 수선·내구성 인챈트: 갈고리는 별도의 내구도 소모를 만들지 않으므로 효과 없음
- 보호·무기 인챈트: 관여하지 않음
- PvP: 다른 플레이어와 몹을 끌어오지 않음

## 15. 자동 검증

구현 시 다음 스크립트를 추가한다.

- `tools/validate.mjs`
  - 모든 JSON 파싱
  - 함수·태그·predicate·recipe 참조 확인
  - 데이터팩 형식과 폴더명 확인
  - 동적 레지스트리와 feature flag 부재 확인
  - 틱 호출 그래프의 범위 없는 `@e` 거부
  - `toybox`/`enchant_plus` 네임스페이스 침범 거부
- `tools/test_server.ps1`
  - 알아보기 쉬운 작업 관리자 창 제목 사용
  - 공식 서버 JAR 실행
  - 최초 로드, `/reload`, 저장 후 재시작 로그 수집
- `tools/test_all.ps1`
  - 정적 검증과 서버 검증 순차 실행
- `tools/package.ps1`
  - 임시 경로를 안전하게 정리
  - 릴리스 ZIP과 SHA-256 생성
  - 원본 소스와 무관한 파일 제외

## 16. 실제 클라이언트 시험표

자동화가 통과해도 아래 항목은 실행하기 전까지 통과로 기록하지 않는다.

### 기본 조작

- 바닥, 벽, 천장에 각각 고정
- 허공 빗맞힘
- 5, 15, 29, 31블록 거리
- 두 번째 우클릭 해제
- 웅크리기 해제
- 도착 자동 종료
- cooldown 중 재사용

### 충돌

- 완전한 벽, 한 칸 구멍, 낮은 천장
- 반 블록, 계단, 울타리, 벽, 열린 문, 닫힌 문
- 덩굴, 꽃, 잔디, 눈 층
- 월드 보더 근처
- 아직 로드되지 않은 청크 방향

### 환경과 상태

- 물에 던지기
- 견인 중 입수
- 용암 접촉
- 탈것 탑승
- 겉날개 비행 시작
- 사망, 로그아웃, 서버 재접속, 차원 이동
- 갈고리를 던진 뒤 손 아이템 교체

### 멀티플레이

- 두 명이 떨어져서 동시 사용
- 두 명이 같은 블록에서 같은 방향으로 동시 사용
- 서로의 줄이 교차하는 위치
- 한 명이 사용 중 사망·로그아웃
- 일반 낚싯대 사용자와 갈고리 사용자가 바로 옆에서 동시 투척

### 장시간

- 30분 반복 사용
- 남은 `fishing_bobber`, 태그, 점수 누수 확인
- 서버 틱 시간과 로그 오류 확인

## 17. 출시 합격 조건

다음을 모두 만족해야 `v0.1.0`으로 패키징한다.

- 실험적 기능 경고를 유발하는 레지스트리 파일 없음
- 공식 26.2 서버 최초 로드·`/reload`·재시작 오류 없음
- 일반 낚싯대 오작동 0회
- 2인 동시 사용 50회에서 소유자 교차 0회
- 벽 관통과 블록 내부 정지 0회
- 사망·로그아웃·차원 이동 뒤 고아 상태 0회
- 30분 반복 시험 뒤 눈에 띄는 엔티티·점수 누수 없음
- 실제 클라이언트에서 조작감 승인

서버 명령 시험만으로 줄 렌더링, 입력감, 멀티플레이 위치 동기화를 통과했다고 기록하지 않는다.

## 20. 현재 판단

기술적으로 구현 가능한 범위는 **줄이 보이는 블록 고정형 자동 견인 갈고리**다. 원작처럼 자연스러운 진자 운동을 약속하지 않는다.

가장 큰 위험은 이동 계산이 아니라 커스텀 인챈트 없이 `사용한 플레이어 ↔ 새 낚싯찌`를 정확하게 연결하는 부분이다. 따라서 P0를 독립 시험으로 먼저 끝내고, 이 단계가 통과한 경우에만 나머지 파일을 만든다.
