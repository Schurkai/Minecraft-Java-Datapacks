# 인챈트플러스

인챈트플러스 v1.1.4는 Minecraft Java Edition 정식 26.2용 순수 데이터팩이다. 기능 범위를 다음 세 가지로 줄였다.

1. 바닐라 최대 레벨을 유지한 인챈트 중복 허용
2. 날개 결속 흉갑
3. 네더의 별을 쓰는 모루 누적 작업 비용 초기화

Fabric, Forge, Paper, Spigot, Bukkit과 실험적 기능이 필요 없다.

## 대상

- Minecraft Java Edition 정식 26.2
- 데이터팩 형식 107.1
- 선택 리소스팩 형식 88.0
- Realms용 순수 데이터팩

## 인챈트 중복

장비를 모루 왼쪽, 인챈트된 책을 오른쪽에 넣는다. 다음 묶음은 한 아이템에 함께 적용할 수 있다.

| 장비 | 허용 조합 | 최대 레벨 |
|---|---|---|
| 검 | 날카로움 + 강타 + 살충 | 각각 V |
| 철퇴 | 육중 + 격파 + 날카로움 + 강타 + 살충 | 격파 IV, 나머지 V |
| 방어구 | 보호 + 폭발로부터 보호 + 화염으로부터 보호 + 발사체로부터 보호 | 각각 IV |
| 활 | 수선 + 무한 | 각각 I |
| 쇠뇌 | 다중 발사 + 관통 | 다중 발사 I, 관통 IV |

그 밖의 인챈트도 26.2 바닐라 최대 레벨을 유지한다. 섬세한 손길+행운, 급류+충성/집전, 찌르기+철퇴 피해 인챈트는 계속 제한한다.

v1.1.4는 `data/*/enchantment/*.json` 레지스트리 항목을 하나도 포함하지 않는다. 공식 인챈트 정의와 최대 레벨은 그대로 두고, 정확히 4개의 바닐라 배타 태그와 날카로움 지원 아이템 태그만 좁게 바꾼다. 외부 팩의 인챈트 레지스트리 항목 때문에 발생하던 실험 수명주기를 피하기 위한 변경이다.

육중은 바닐라 철퇴 인챈트이며 최대 레벨은 바닐라와 같은 V다.

설치·교체 직후에는 `/reload`를 실행하고 열려 있던 모루 화면을 닫았다 다시 연다.

## 날개 결속 흉갑

제작 칸에서 흉갑 1개와 겉날개 1개를 합친다. 모루 조합이 아니다.

가죽·구리·사슬·금·철·다이아몬드·네더라이트 흉갑을 지원한다. `minecraft:crafting_transmute`로 원본 흉갑의 구성요소를 이어받고 `minecraft:glider`를 추가한다.

분리하려면 날개 결속 흉갑을 `Q`키로 숫돌 윗면에 올린다. 투척 뒤 약 3초 동안 플레이어 주변을 검사하며, 성공하면 일반 흉갑과 겉날개 1개로 돌아온다. 흉갑의 인챈트, 내구도, 장식, 누적 작업 비용, 사용자 이름·로어와 사용자 지정 데이터는 유지한다. 이미 분리된 흉갑을 다시 검사해도 겉날개가 추가로 나오지 않는다.

## 모루 누적 비용 초기화

저장된 `repair_cost`가 1 이상인 아이템만 설명창 첫 줄에 `누적 작업 비용: +숫자레벨`이 표시된다. 비용이 없거나 0인 일반 아이템에는 표시하지 않는다.

1. 설명에 누적 작업 비용이 `+1레벨` 이상으로 표시된 아이템과 네더의 별을 준비한다.
2. 두 아이템을 `Q`키로 같은 모루 윗면에 가깝게 던진다. 별을 던진 뒤 약 4초 안에 두 아이템이 모루 위에 놓이면 된다.
3. 소리와 입자가 나오면 별 1개가 소모되고 누적 작업 비용이 0으로 초기화된다.

이름, 내구도, 인챈트, 장식, 기존 로어와 사용자 지정 데이터는 유지한다. 초기화 뒤에는 `+0레벨` 줄도 남지 않는다. `/trigger ep_anvil`은 초기화가 아니라 사용법 안내만 표시한다.

바닐라의 한 작업당 40레벨 상한은 순수 데이터팩으로 바꿀 수 없다. 여러 책을 한 번에 합치지 말고 하나씩 적용하면서 필요할 때 재련한다.

## 제거한 기능

v1.1.4에는 폭렬, 균열 사격, 도약, 갈고리, 바람 병, 포션 합성, 줄자, 분필, 분필 나침반, 점프 발판, 수확 낫, 수프 냄비가 없다. 레시피·발전 과제·함수·틱 처리·도움말·번역도 함께 제거했다.

`toybox:blast`, `toybox:rift_shot`, `toybox:springstep`, `toybox:grappling` 호환 정의도 실험 수명주기를 피하기 위해 완전히 제거했다. 이 커스텀 인챈트가 붙은 오래된 아이템은 월드 백업 뒤 처리해야 한다.

## 포션 계획

기존의 “양손에 포션을 들고 양조기 사용” 방식은 제거했다. 레드스톤과 발광석을 순서와 관계없이 모두 적용하는 요구사항은 보류 목록에 남겼다.

26.2 정식에는 데이터팩용 양조 레시피 타입이 없다. `minecraft:brewing`은 26.3 스냅샷에서 처음 데이터 기반으로 공개됐으므로, 스냅샷을 Realm 대상에 섞지 않는다. 26.3 정식 출시 뒤 실제 양조기 레시피로 구현하는 것을 우선안으로 삼는다. 자세한 내용은 `DESIGN_ALCHEMY.md`를 본다.

## 설치

1. 월드를 백업한다.
2. `Enchant_Plus_v1.1.4-java-26.2.zip`을 월드의 `datapacks` 폴더에 넣는다.
3. 기존 Realm Toybox 또는 이전 인챈트플러스 ZIP은 제거한다. 내부 `toybox` 네임스페이스가 같아 동시에 설치하면 안 된다.
4. 월드에서 `/reload`를 실행한다.
5. `/datapack list enabled`와 `/trigger ep_help`로 확인한다.

Realm은 데이터팩을 넣은 로컬 월드를 업로드한다. 팩 선택 화면의 `팩 (세계)` 표시는 월드 내 데이터팩이라는 뜻이며 실험 기능 표시가 아니다.

`v1.1.0`은 인챈트 JSON 오버라이드 때문에 Realm용으로 사용하지 않는다. 배포 폴더의 최신 `v1.1.4`만 넣고, 세계 생성 화면에서 여전히 실험 기능 경고가 뜨면 진행하지 말고 기존 데이터팩과 월드 자체의 실험 설정을 먼저 확인한다.

공개 명령은 제품명에 맞춰 `ep_help`, `ep_anvil`을 쓴다. v1.1.2 이하에서 쓰던 `tb_*` 공개 objective는 첫 로드 때 새 이름으로 마이그레이션한 뒤 제거한다. 저장 아이템과 옛 월드 호환 때문에 내부 데이터 네임스페이스 `toybox`만 유지한다.

## 언어

리소스팩 없이도 기능이 작동하며 기본 문구는 한국어다. 선택 리소스팩을 적용하면 한국어 클라이언트는 한국어, 그 밖의 언어는 영어로 표시된다.
