# TEST REPORT

작성일: 2026-08-22
대상: 인챈트플러스 v1.1.4 / Minecraft Java Edition 정식 26.2

## 결론

v1.1.0의 바닐라 인챈트 JSON 오버라이드는 외부 데이터팩의 동적 레지스트리 항목으로 취급되어 26.2에서 `Lifecycle.experimental`이 될 수 있었다. v1.1.1에서 해당 JSON 12개와 커스텀 인챈트 정의 4개를 모두 제거하고 태그 전용으로 다시 구현했다. v1.1.2에서는 자동시험용 함수와 인챈트 적용 아이템 수정자까지 별도 테스트 하네스로 분리해 배포 ZIP에서 제거했다. v1.1.3은 공개 명령·번역과 모루 비용 기능을 수정했고, v1.1.4는 숫돌 위 날개 결속 분리를 추가했다.

정적 검증, 소스 디렉터리 서버 시험과 최종 배포 ZIP 서버 시험은 통과했다. 실제 클라이언트 세계 생성 경고 화면과 Realm 업로드는 수동 미실행이므로 통과로 기록하지 않는다.

## Realm 안전성 검사

- `pack.mcmeta`에 `features` 없음
- 모든 네임스페이스의 `data/<namespace>/enchantment/*.json` 파일 0개
- 최종 ZIP의 동적 인챈트 레지스트리 파일 0개
- 최종 ZIP의 `dev` 함수·아이템 수정자 0개
- 최종 ZIP 런타임의 `max_level` 정의와 `/enchant` 명령 0개
- 모루 재련 런타임과 사용자 문서의 자수정 참조 0개, 촉매 ID는 `minecraft:nether_star`만 사용
- 공식 26.2 클라이언트의 `CreateWorldScreen` 바이트코드에서 경고 조건이 실험 기능 플래그 또는 비안정 레지스트리 수명 주기임을 확인
- 공식 26.2의 `ResourceManagerRegistryLoadTask` 바이트코드에서 외부 팩의 동적 레지스트리 항목이 `Lifecycle.experimental`로 등록될 수 있음을 확인
- 변경 데이터는 `exclusive_set` 태그 4개와 `sharp_weapon` 아이템 태그 1개뿐
- 공식 서버가 생성한 `level.dat`에 `enabled_features` 항목 없음
- `minecart_improvements`, `redstone_experiments`, `trade_rebalance`는 모두 `Disabled`
- 데이터팩은 `file/Enchant_Plus.zip`으로 정상 활성화

태그 변경 범위는 공식 26.2 생성 데이터와 비교했다.

- `damage`: 공식 6종 중 찌르기만 남겨 나머지 피해 5종끼리 허용
- `armor`: 공식 값이 보호 4종뿐임을 확인한 뒤 비움
- `bow`: 공식 값이 수선·무한뿐임을 확인한 뒤 비움
- `crossbow`: 공식 값이 다중 발사·관통뿐임을 확인한 뒤 비움
- `sharp_weapon`: 기존 태그에 철퇴만 병합하며, 공식 데이터에서 이 태그를 지원 대상으로 쓰는 인챈트는 날카로움뿐임을 확인
