# AUDIT

## 결론

인챈트플러스 v1.1.4는 Minecraft Java Edition 정식 26.2와 데이터팩 형식 107.1을 대상으로 한다. 기능 범위를 인챈트 중복, 날개 결속 흉갑, 네더의 별 모루 재련으로 축소했다.

## 유지한 데이터

바닐라 인챈트 JSON 43개는 하나도 오버라이드하지 않는다. 공식 최대 레벨, 비용, 가중치와 효과 공식은 전부 공식 26.2 데이터 그대로다.

호환성은 다음 태그 5개만 바꿔 구현한다.

- `minecraft:exclusive_set/damage`: 찌르기만 남겨 날카로움·강타·살충·육중·격파끼리는 허용하고 찌르기와의 제한은 유지
- `minecraft:exclusive_set/armor`: 공식 값이 정확히 보호 4종뿐임을 확인한 뒤 비워 4종 동시 적용 허용
- `minecraft:exclusive_set/bow`: 공식 값이 무한·수선뿐임을 확인한 뒤 비워 동시 적용 허용
- `minecraft:exclusive_set/crossbow`: 공식 값이 다중 발사·관통뿐임을 확인한 뒤 비워 동시 적용 허용
- `minecraft:enchantable/sharp_weapon`: 기존 값에 철퇴만 병합해 날카로움 책의 철퇴 모루 적용 허용

빈 태그 3개는 각각 공식 태그의 두 개 또는 네 개 인챈트에만 연결되며 다른 배타 묶음에는 영향을 주지 않는다. 섬세한 손길+행운, 급류+충성/집전 제한은 손대지 않는다.

26.2의 `ResourceManagerRegistryLoadTask`는 알려진 공식 팩이 아닌 데이터팩에서 읽은 동적 레지스트리 항목에 `Lifecycle.experimental`을 부여한다. 따라서 v1.1.0의 바닐라 인챈트 JSON 12개와 비활성 커스텀 인챈트 4개를 모두 제거했다. v1.1.4에는 어떤 네임스페이스에도 `data/<namespace>/enchantment/*.json` 파일이 없다.

배포본에는 자동시험용 `dev` 함수와 인챈트 적용 아이템 수정자도 없다. 이들은 소스의 `tools/test_harness` 아래 별도 시험 팩으로 격리되며, 공식 서버 자동 시험 때만 함께 설치된다. 런타임 데이터에는 `max_level` 정의와 `/enchant` 명령이 모두 0개다.

날개 결속 레시피는 7개만 남겼다. 모두 `crafting_transmute`이며 흉갑을 입력으로, 겉날개를 재료로, 같은 등급 흉갑과 `glider` 구성요소를 결과로 사용한다.

분리는 일반 아이템 투척 통계가 연 60틱 창에서 해당 플레이어 4블록 주변만 검사한다. 숫돌 윗면의 지원 흉갑에 저장된 `glider`가 있을 때만 결속 제작이 추가한 네 구성요소를 제거하고 겉날개 1개를 생성한다. 제거 성공을 다시 확인한 뒤에만 겉날개를 생성하므로 같은 아이템의 재검사로 복제되지 않는다.

모루 설명은 `inventory_changed` 사건에서 저장된 원시 `repair_cost`만 읽는다. 값이 1 이상일 때만 관리 로어를 넣고, 0이거나 없으면 옛 관리 로어를 제거하므로 일반 아이템에 `+0레벨`이 붙지 않는다.

재련은 `minecraft.dropped:minecraft.nether_star` 플레이어 통계가 해당 플레이어에게 80틱 검사 창을 여는 방식이다. 활성 플레이어의 4블록 안만 검사하며 루트 tick에는 전역 `@e` 검색이 없다. 가까운 비용 0 아이템은 건너뛰고 저장 비용이 양수인 첫 대상의 `repair_cost`만 제거한 뒤 별을 정확히 1개 소비한다.

## 제거 감사

다음 기능의 획득 레시피, 발전 과제, 런타임 함수, 태그, predicate, 틱 호출과 번역을 제거했다.

- 폭렬·균열 사격·도약·갈고리
- 바람 병
- 포션 합성
- 줄자·분필·분필 나침반
- 점프 발판
- 수확 낫
- 수프 냄비

커스텀 인챈트 ID 4개의 비활성 호환 정의도 실험 수명주기를 피하기 위해 제거했다. 업데이트 시 로드된 수프 marker, 갈고리 낚시찌와 플레이어 임시 태그는 1회 정리한다.

v1.1.4의 tick 함수는 `ep_help`, `ep_anvil`, 데이터 버전과 투척 사건을 확인한다. 모루 재련은 최대 80틱, 숫돌 분리는 최대 60틱 동안 사건을 일으킨 플레이어 주변만 검사하며 루트 tick의 전역 엔티티 검색은 없다.

## 포션 판정

26.2 공식 서버의 `minecraft:recipe_serializer`와 `minecraft:recipe_type` 레지스트리에는 양조 레시피가 없다. Mojang은 26.3 Snapshot 3에서 `minecraft:brewing`을 처음 데이터 기반 레시피로 공개했다.

따라서 26.2 Realm용 팩에 양조기 슬롯을 감시·변조하는 자체 엔진을 넣지 않았다. 기존 포션 합성은 제거했고, 레드스톤과 발광석 양방향 병용은 26.3 정식 출시 후 네이티브 레시피로 재검토한다.

공식 참고: https://www.minecraft.net/en-us/article/minecraft-26-3-snapshot-3

## 검증 경계

정적 검증은 동적 인챈트 레지스트리 파일이 0개인지, 공식 26.2의 배타 태그 구성과 최대 레벨 전제가 그대로인지, 태그 변경 범위, 남은 레시피 목록, 제거 경로, 함수 참조, tick 호출 그래프와 번역을 검사한다.

공식 서버 자동 시험은 로드, `/reload`, 재시작, 태그 기반 인챈트 호환 게이트와 모루 재련을 검사한다. 실제 클라이언트의 실험 경고 화면, 모루·제작 UI와 Realm 업로드는 별도 수동 시험으로 남긴다.
