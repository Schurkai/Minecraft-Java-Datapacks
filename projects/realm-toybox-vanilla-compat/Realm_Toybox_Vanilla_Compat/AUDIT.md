# AUDIT

## 결론

이 변형판은 Minecraft Java Edition 정식 26.2, 데이터팩 형식 107.1을 대상으로 한다. 스냅샷·프리릴리스용 데이터는 사용하지 않았다.

바닐라 인챈트 43개 중 12개만 오버라이드한다. 각 파일은 공식 서버가 생성한 26.2 데이터와 객체 단위로 비교한다. 승인된 `exclusive_set` 변경과 날카로움의 철퇴 지원 추가 외에 비용, 가중치, 효과 계산식과 최대 레벨은 바닐라 그대로다.

## 허용한 차이

| 오버라이드 | 변경 |
|---|---|
| `sharpness`, `smite`, `bane_of_arthropods`, `density`, `breach` | 공식 damage 집합 대신 찌르기만 담은 `#toybox:exclusive_set/trident_damage` 사용 |
| `sharpness` 추가 변경 | 공식 날붙이 태그에 철퇴 하나만 더한 `#toybox:enchantable/sharpness_plus_mace` 사용 |
| `protection`, `blast_protection`, `fire_protection`, `projectile_protection` | armor 배타 집합 제거 |
| `infinity` | bow 배타 집합 제거 |
| `multishot`, `piercing` | crossbow 배타 집합 제거 |

철퇴 피해 5종은 서로 허용하지만 `trident_damage`의 `impaling`과는 계속 배타적이다. 강타와 살충은 공식 `#minecraft:enchantable/weapon`이 이미 철퇴를 포함한다. 날카로움은 공식 지원 대상에 철퇴가 없어 별도 태그로 철퇴 하나만 추가했다. `primary_items`는 바꾸지 않아 날카로움이 철퇴의 마법부여대 기본 후보로 새로 등장하지는 않는다.

## 바닐라 데이터 보호

- `data/minecraft/tags/enchantment/exclusive_set` 디렉터리를 패키지에 넣지 않는다.
- 빈 `exclusive_set` 태그가 없다.
- 행운, 섬세한 손길, 급류, 충성, 집전, 찌르기 파일을 오버라이드하지 않는다.
- 변경 없는 바닐라 인챈트 JSON을 복사하지 않으므로 다른 31개 정의는 서버의 26.2 원본을 직접 쓴다.
- 보호 효과·폭발 넉백 저항 계산식도 공식 IV 상한과 함께 원본으로 복원했다.

## 상한 우회 감사

고등 마법부여의 발전 과제 진입점, `advanced_enchant` 함수·아이템 수정자와 VI–X 시험 아이템을 모두 제거했다. 데이터 트리와 번역 파일에 해당 참조가 남지 않았음을 자동 검사한다.

이미 월드에 존재하는 상한 초과 아이템을 자동으로 낮추는 코드는 없다. 이는 플레이어 아이템을 파괴적으로 수정하지 않기 위한 정책이며 제한 사항에 기록했다.

## 기능·성능 감사

인챈트 변경은 레지스트리 JSON이며 매 틱 엔티티 검색을 추가하지 않는다. 새 런타임 스모크 함수는 개발자가 명시적으로 호출하는 `dev/server_smoke`에서만 도달하며 tick 호출 그래프에 없다. 기존 Realm 지향 사건 기반 구조는 유지했다.

날개 결속 흉갑은 기존 `crafting_transmute` 레시피 7개를 유지한다. 정적 검증은 각 레시피가 해당 흉갑, 겉날개 재료, 같은 등급 결과와 `minecraft:glider` 구성요소를 가지는지 확인한다. 순수 데이터팩에는 사용자 정의 모루 레시피 레지스트리가 없어 겉날개 결합을 모루로 위장하지 않는다.

모루 누적 작업 비용은 `inventory_changed`와 `default_block_use` 발전 과제 사건으로 처리한다. 인벤토리 사건은 `minecraft:repair_cost`가 있는 고정 플레이어 슬롯만 순회해 정확한 값을 관리 로어 첫 줄에 반영한다. 첫 등록은 `set_lore`의 `insert`, 이후 갱신은 `replace_section(offset=0,size=1)`을 쓰므로 기존 로어는 지우지 않는다.

아이템 투척 감지는 인벤토리 사건 뒤 1틱에 한 번만 예약된다. 태그가 붙은 플레이어 각각의 4블록 주변에서 아이템 엔티티를 찾고, 같은 모루 위 1.5블록 안의 네더의 별과 `repair_cost` 대상 하나를 짝짓는다. 성공 확인 뒤 별 묶음 수량을 1만 줄인다. tick 호출 그래프에는 이 스캐너가 없으며 매 틱 전역 엔티티 검색을 추가하지 않았다.

재련은 로어를 0으로 바꾼 다음 `repair_cost` 구성요소만 제거한다. 이름, 내구도, 인챈트, 장식, 기존 로어와 커스텀 데이터는 보존된다. 이전 무료 `/trigger tb_anvil` 경로는 제거하고 안내만 남겼다.

바닐라 모루의 단일 작업 40레벨 상한은 데이터팩 레지스트리나 게임 규칙으로 노출되지 않는다. 이 팩은 네더의 별 재련으로 반복 작업의 저장 페널티를 제거하지만, 한 번의 작업 자체가 40레벨 이상인 경우까지 상한을 해제한다고 주장하지 않는다.

순수 데이터팩이며 모드 로더나 서버 플러그인 의존성이 없다. `pack.mcmeta`에 실험적 `features` 선언도 없다.

## 검증 방식과 경계

- 자동 정적 검증: 공식 26.2 생성 JSON과 12개 오버라이드를 객체 단위 비교한다.
- 공식 서버 검증: 소스와 최종 ZIP을 각각 신규 부팅, 실제 `/reload`, 전체 스모크, 정상 종료, 같은 월드 재시작한다.
- 헤드리스 서버는 온라인 플레이어가 없어 `/enchant`와 모루 UI 순서를 직접 자동화할 수 없다. 런타임 스모크는 편집된 정의의 로드·아이템 적용·바닐라 레벨 범위를 확인하고, 실제 모루 조합 순서는 수동 시험으로 남긴다. 실행하지 않은 수동 시험은 통과로 기록하지 않는다.
