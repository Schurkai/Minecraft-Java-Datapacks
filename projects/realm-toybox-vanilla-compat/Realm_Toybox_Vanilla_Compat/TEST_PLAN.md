# TEST PLAN

## 1. 정적 검증

`node tools/validate_compat.mjs`

필수 확인 항목:

- 모든 JSON과 `pack.mcmeta` 파싱
- 데이터팩 107.1, 리소스팩 88.0
- 공식 26.2 인챈트 43개 확인
- 오버라이드는 승인된 12개뿐인지 확인
- 각 오버라이드가 공식 정의와 승인된 배타 변경 외에는 같은지 확인
- 날카로움 지원 태그가 공식 날붙이 + 철퇴 하나뿐인지 확인
- 모든 바닐라 `max_level` 유지
- 바닐라 배타 태그 오버라이드와 빈 배타 태그 없음
- 행운/섬세한 손길 및 급류/충성/집전 정의 미변경
- 고등 마법부여와 VI–X 시험 경로 없음
- 로컬 함수 참조, load/tick 태그, 한·영 번역 키 해석
- 호환성 스모크가 tick 그래프에서 호출되지 않음
- 날개 결속 7종 레시피의 흉갑 입력, 겉날개 재료, 같은 등급 결과와 `glider` 구성요소 확인
- 누적 비용 로어 갱신과 투척 감지가 `inventory_changed` 사건 및 1틱 예약으로만 실행되는지 확인
- 로어 삽입·첫 줄 교체가 사용자 로어를 보존하고 플레이어 핫바·일반 인벤토리·보조 손·방어구 슬롯을 처리하는지 확인
- 재련 스캐너가 tick 그래프에 없고 플레이어 4블록 주변으로 제한되는지 확인
- 대상은 양수 `repair_cost`, 촉매는 네더의 별, 성공당 소모량은 1개인지 확인
- 초기화 수정자가 `repair_cost`만 제거하는지 확인

## 2. 공식 서버 자동 시험

```powershell
& .\tools\test_server.ps1 -ServerJar ..\server-26.2.jar -PackArtifact .
```

소스 디렉터리와 최종 ZIP에 각각 실행한다.

1. 서버 JAR SHA-1과 내부 `version.json`의 정식 26.2·데이터 형식 107.1 확인
2. 새 평지 월드 부팅과 팩 자동 로드
3. 실제 `/reload`
4. `toybox:dev/server_smoke` 실행
5. 편집된 인챈트 12개 로드와 검·철퇴·흉갑·활·쇠뇌 조합 아이템 직렬화, 공식 최대 범위 확인
6. 누적 비용 로어 삽입·제자리 갱신, 동적 값 7·15, 기존 로어와 커스텀 데이터 보존 확인
7. 모루 위 의식에서 `repair_cost=31→0`, 네더의 별 `2→1`, 로어 값 `0`, 다른 구성요소 보존 확인
8. 기존 포션 합성, 건축 도구, 점프 발판, 수프 냄비, 수확 낫, 측량 기능 회귀 점수 확인
9. JSON·명령·함수·레지스트리 오류 로그 검색
10. `save-all`, 정상 종료
11. 같은 월드 재시작 후 스모크 재실행
12. 포트, PID 파일, 잠금 파일과 소유 JVM 잔존 여부 확인

성공 조건은 두 부팅 모두 `$smoke_fail=0`이며, 활성 데이터팩 목록에 Vanilla Compat 하나만 있는 것이다.

## 3. 실제 클라이언트 수동 시험

이 절은 실제 26.2 클라이언트에서 실행하고 결과를 `TEST_REPORT.md`에 별도로 기록한다. 자동 서버 시험으로 대체했다고 기록하면 안 된다.

### 허용 조합

모루에서 책 적용 순서를 앞뒤로 바꿔 각각 확인한다.

- 다이아몬드 검: 날카로움 V → 강타 V → 살충 V
- 새 다이아몬드 검: 살충 V → 강타 V → 날카로움 V
- 철퇴: 육중 V → 격파 IV → 날카로움 V → 강타 V → 살충 V
- 새 철퇴: 살충 V → 강타 V → 날카로움 V → 격파 IV → 육중 V
- 다이아몬드 흉갑: 보호 IV → 폭발 보호 IV → 화염 보호 IV → 발사체 보호 IV
- 새 흉갑: 위 순서의 역순
- 활: 수선 I → 무한 I
- 새 활: 무한 I → 수선 I
- 쇠뇌: 다중 발사 I → 관통 IV
- 새 쇠뇌: 관통 IV → 다중 발사 I

각 결과에서 인챈트 목록, 레벨, 모루 재료·경험치 소모와 실제 사용 동작을 확인한다.

제작 칸에서 가죽·구리·사슬·금·철·다이아몬드·네더라이트 흉갑을 각각 겉날개와 합쳐 날개 결속 결과가 나오는지 확인한다. 이 절은 모루 시험이 아니다.

### 모루 누적 비용

- 모루 결과를 인벤토리에 넣었을 때 설명창 첫 줄에 실제 `repair_cost` 숫자가 표시되는지 확인
- 사용자 로어가 있던 아이템은 비용 줄 아래에 기존 로어가 그대로 유지되는지 확인
- 누적 작업 아이템과 네더의 별 2개 묶음을 같은 모루 위에 던지면 효과가 나고 별이 1개만 줄어드는지 확인
- 회수한 아이템의 설명창이 `+0레벨`이고 다음 저비용 모루 작업이 가능한지 확인
- 비용이 없거나 0인 아이템, 모루 밖에 던진 조합, 대상과 별이 멀리 떨어진 조합에는 별이 소모되지 않는지 확인
- 이름, 내구도, 인챈트, 장식, 사용자 지정 이름과 커스텀 데이터가 유지되는지 확인
- `/trigger tb_anvil set 1`이 아이템을 바꾸지 않고 재련 안내만 표시하는지 확인
- 단일 작업 계산 자체가 40레벨 이상인 시험은 여전히 거부되는지 확인하고 바닐라 상한 우회로 기록하지 않기

### 유지해야 하는 거부 조합

- 곡괭이: 섬세한 손길 I + 행운 III 거부
- 삼지창: 급류 III + 충성 III 거부
- 삼지창: 급류 III + 집전 I 거부
- 쇠뇌: 폭렬 + 다중 발사 또는 관통 거부

### 상한

- 명령 없이 일반 마법부여대·책·모루만 사용해 날카로움 VI, 보호 V, 관통 V 등 바닐라 상한 초과 결과가 나오지 않는지 확인한다.
- 고등 마법부여대를 사용하던 기존 조작이 아무 동작도 하지 않는지 확인한다.

### 언어·Realm

- 리소스팩 + 한국어: 변형판 제목과 인챈트 안내가 한국어
- 리소스팩 + 한국어 외 언어: 영어
- 리소스팩 없음: 영어 fallback, 기능 정상
- 백업 월드를 Realm에 업로드해 실험적 기능 경고 없이 로드, 재접속·서버 재시작 후 유지
- 두 플레이어가 가까운 서로 다른 모루에서 동시에 재련할 때 대상과 촉매가 섞이지 않는지 확인

## 4. 패키징

`tools/package.ps1`과 리소스팩 `package.ps1`을 각각 두 번 실행한다.

- ZIP 루트에 `pack.mcmeta` 존재
- 경로 구분자는 `/`
- 데이터팩에 `tools/`와 변동 가능한 `TEST_REPORT.md` 미포함
- 같은 입력의 두 SHA-256이 동일
- 최종 ZIP 자체가 공식 서버 시험 통과
