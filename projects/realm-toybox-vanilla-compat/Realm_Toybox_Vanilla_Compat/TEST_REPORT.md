## 개발 중 발견해 수정한 시험 문제

- compat4 첫 서버 실행은 테스트 함수가 로어 목록 인덱스 뒤에 곧바로 복합 조건을 붙인 잘못된 NBT 경로를 사용해 함수 파싱 단계에서 실패했다. 목록 복합 선택자로 수정하고 처음부터 재실행했다. 이 실행은 통과로 기록하지 않았다.
- 첫 동적 로어 구현은 `set_lore` 해석 엔티티를 지정하지 않아 저장소 숫자가 설명창에 미해석 NBT 구성요소로 남았다. `entity: this`를 지정하고 실제 실행자 엔티티 문맥에서 값 `7`, `15`, `0`이 텍스트로 해석되는지 재검증했다. 값 검증이 0이었던 실패 실행들은 통과로 기록하지 않았다.
- 26.2가 해석한 숫자 텍스트는 단순 `{text:"0"}`이 아니라 빈 루트와 `extra` 자식으로 직렬화됐다. 서버가 실제 생성한 정규형을 확인한 뒤 의미값을 검사하도록 스모크를 고쳤다.
- 첫 자동 초기화 구현은 플레이어 슬롯을 `inventory.0..35`로 가정해 공식 서버가 `inventory.27`을 알 수 없는 슬롯으로 거부했다. 26.2 명령 슬롯에 맞춰 일반 인벤토리 `inventory.0..26`과 핫바 `hotbar.0..8`로 분리하고 처음부터 다시 시험했다. 실패 실행은 통과로 기록하지 않았다.
- 사용자 지정 이름 보존 스모크가 직렬화된 텍스트 구성요소를 지나치게 구체적인 SNBT 모양으로 비교해 3/4로 실패했다. 이름 구성요소 존재와 나머지 정확한 구성요소를 분리해 검사한 뒤 4/4를 재확인했다.
- `/enchant`는 헤드리스 갑옷 거치대와 몹을 플레이어처럼 처리하지 않아 호환성 성공 여부를 반환하지 않았다. 이를 실제 조합 통과로 기록하지 않았다.
- `enchant_randomly`의 `only_compatible`은 기존 인챈트와의 배타성을 검증하는 수단이 아니어서, 거부 조합 자동 판정에 사용하지 않았다.
- 수확 낫 3×3 시험은 좌표 `(-1,-1)`이 다른 청크라는 사실을 반영하지 않고 `(0,0)`만 강제 로드했다. 경계 네 청크를 명시적으로 로드·해제하고 시험용 갑옷 거치대를 fixture 밖으로 옮긴 뒤, 9개 배치·9개 수확과 전체 0을 처음부터 재확인했다.
