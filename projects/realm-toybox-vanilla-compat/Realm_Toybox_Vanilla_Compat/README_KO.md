# Realm Toybox Vanilla Compat

`v0.9.0-compat4`는 Realm Toybox의 기능은 유지하면서 바닐라 인챈트 최대 레벨을 복원하고, 요청한 인챈트 조합과 네더의 별을 쓰는 모루 재련을 제공하는 별도 변형판이다.

- 대상: Minecraft Java Edition 정식 26.2
- 데이터팩 형식: 107.1
- 선택 리소스팩 형식: 88.0
- 순수 데이터팩: Fabric, Forge, Paper, Spigot, Bukkit 불필요
- 실험적 기능 요청 없음

## 달라진 인챈트

다음 묶음은 같은 아이템에 함께 적용할 수 있다.

| 묶음 | 최대 레벨 |
|---|---:|
| 날카로움 + 강타 + 살충 | 각각 V |
| 철퇴: 육중 + 격파 + 날카로움 + 강타 + 살충 | 육중·날카로움·강타·살충 V, 격파 IV |
| 보호 + 폭발로부터 보호 + 화염으로부터 보호 + 발사체로부터 보호 | 각각 IV |
| 수선 + 무한 | 각각 I |
| 다중 발사 + 관통 | 다중 발사 I, 관통 IV |

그 밖의 모든 바닐라 인챈트도 26.2 기본 최대 레벨을 그대로 쓴다. 예를 들어 힘 V, 효율 V, 내구성 III, 행운 III, 약탈 III, 찌르기 V, 육중 V다. 날카로움의 지원 아이템에는 철퇴 하나만 추가했으며, 마법부여대의 기본 등장 대상을 넓히지는 않았다.

위 조합은 인챈트된 책이나 같은 종류 장비를 **모루에서 합치는 방식**으로 적용한다. 데이터 정의는 양쪽 배타 판정을 해제했지만 실제 클라이언트 모루 UI 양방향 시험은 아직 수동 시험 항목으로 남아 있다.

다음 제한은 풀지 않았다.

- 섬세한 손길 + 행운
- 급류 + 충성 또는 집전
- 찌르기 + 육중·격파·날카로움·강타·살충
- Toybox 폭렬 + 다중 발사·관통·균열 사격

이 변형판에는 바닐라 상한을 넘기던 고등 마법부여 시스템과 해당 시험 키트가 없다. Toybox 전용 인챈트는 자체 설계 상한을 유지한다: 폭렬 III, 도약 III, 균열 사격 I, 갈고리 I.

## 모루의 `Too Expensive!` 완화

모루 작업을 거쳐 `minecraft:repair_cost`가 생긴 아이템은 설명창 첫 줄에 `누적 작업 비용: +숫자레벨`이 표시된다. 이 숫자는 현재 조합의 총 경험치가 아니라 바닐라가 아이템에 저장한 **과거 작업 페널티**다. 기존 사용자 로어는 그 아래에 그대로 보존된다.

초기화 방법은 다음과 같다.

1. 누적 작업 비용이 있는 아이템과 네더의 별을 준비한다.
2. 두 아이템을 같은 모루 위에 함께 던진다.
3. 소리와 입자가 나오면 네더의 별 1개가 소모되고, 대상 아이템의 누적 작업 비용과 설명창 값이 `0`으로 바뀐다.

네더의 별 묶음을 던져도 성공 1회당 정확히 1개만 소모한다. 비용이 없거나 0인 아이템, 모루 위에 있지 않은 아이템에는 별을 쓰지 않는다. 이름, 내구도, 인챈트, 장식, 기존 로어와 사용자 지정 데이터는 유지한다. `/trigger tb_anvil set 1`은 이전 버전 호환을 위해 남아 있지만 이제 무료 초기화가 아니라 사용법 안내만 표시한다.

순수 데이터팩은 바닐라 모루의 단일 작업 40레벨 상한 자체를 변경할 수 없다. 따라서 여러 최대 레벨 인챈트를 한 권에 몰아 한 번에 적용해 그 작업 자체가 40레벨 이상이면 여전히 제한될 수 있다. 책을 하나씩 적용하고, 누적 페널티가 커지면 네더의 별 재련을 한 뒤 다음 책을 적용한다.

## 설치

1. 기존 월드를 백업한다.
2. `Realm_Toybox_Vanilla_Compat_v0.9.0-compat4-java-26.2.zip`을 월드의 `datapacks` 폴더에 넣는다.
3. 기존 `Realm_Toybox_v0.9.0-rc1` 데이터팩은 제거한다. 두 팩은 같은 `toybox` 네임스페이스를 쓰므로 동시에 설치하면 안 된다.
4. 월드를 열어 `/reload` 후 `/datapack list enabled`에서 변형판 하나만 활성화됐는지 확인한다.
5. `/trigger tb_help`로 기능 요약을 확인한다.

Realm에는 데이터팩을 넣은 로컬 월드를 업로드한다. 팩 선택 화면에 `팩 (세계)`로 보이는 것은 월드 내 데이터팩이라는 뜻이며, 이 팩은 `features` 실험 플래그를 선언하지 않는다.

## 한국어와 리소스팩

기능에는 리소스팩이 필요 없다. 리소스팩 없이도 영어 fallback으로 동작한다.

한국어 이름과 안내를 보려면 `Realm_Toybox_Vanilla_Compat_Resources_v0.9.0-compat4-java-26.2.zip`을 선택 리소스팩으로 적용한다. 클라이언트 언어가 `한국어`면 한국어, 그 밖의 언어면 `en_us` 영어가 표시된다.

## 유지되는 Toybox 기능

폭렬, 균열 사격, 도약, 갈고리, 점프 발판, 날개 결속 흉갑, 바람 병, 포션 합성, 줄자·분필·분필 나침반, 수확 낫, 수프 냄비 등 기존 v0.9.0-rc1 기능은 유지된다. 모루 누적 비용 초기화는 네더의 별 1개를 쓰는 물리적 재련 방식이다.

날개 결속 흉갑은 **제작 칸에서 흉갑 1개 + 겉날개 1개**를 합친다. 가죽·구리·사슬·금·철·다이아몬드·네더라이트 흉갑 7종을 지원한다. 순수 데이터팩은 새 모루 레시피를 등록할 수 없으므로 이 결합만은 모루가 아니라 제작 조합이다.

## 개발·검증

PowerShell에서 프로젝트 루트 기준으로 실행한다.

```powershell
node .\Realm_Toybox_Vanilla_Compat\tools\validate_compat.mjs
& .\Realm_Toybox_Vanilla_Compat\tools\test_server.ps1 -ServerJar .\server-26.2.jar -PackArtifact .\Realm_Toybox_Vanilla_Compat
& .\Realm_Toybox_Vanilla_Compat\tools\package.ps1
& .\Realm_Toybox_Vanilla_Compat\tools\test_all.ps1 -ServerJar .\server-26.2.jar
```

검증·패키징·서버 프로세스에는 `Realm_Toybox.vanilla_compat.*` 식별자를 붙인다. 서버 JVM 명령줄에는 job, run ID, 프로젝트 이름이 기록되며 PID/잠금 파일로 고아 프로세스를 정리한다.

실행 결과와 미실행 항목은 `TEST_REPORT.md`, 시험 절차는 `TEST_PLAN.md`, 제한은 `KNOWN_LIMITATIONS.md`를 본다.
